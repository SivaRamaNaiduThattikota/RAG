MODULE 11 · CONCEPT 08

A prompt string isn't an answer yet.
Decoding the response the model actually reads out.

Concept 07 assembled one 954-token string -- system instructions, five boundary-marked chunks, the query -- and handed it off. This concept is the very next step: the model reads that exact string, computes a probability over every possible next token, picks one, repeats until it stops, and the pipeline attaches a citation to whatever came out. Same evidence set, same instructions, two different outcomes -- because the model can only ever answer from what actually survived into the string it read.

PROGRESSIVE BEGINNER CORE

Concept 07 built the string. This concept is what happens when the model reads it.

Everything up through Concept 07 is preparation: hash, chunk, embed, store, rank, select, assemble. Nothing has generated an answer yet. This concept is the step where the model actually reads the assembled string, computes probabilities over its vocabulary one token at a time, and produces the text a user will actually see.

01 · CONCEPT FIRST

Reading the letter, not writing it

Concept 07 wrote the letter -- instructions, cited evidence, the question, in that order. This concept is someone reading that exact letter and answering, out loud, one word at a time, based only on what's actually written on the page in front of them -- not on what they might otherwise know or guess.

First memory: generation is decoding from the string that was actually assembled -- not from the corpus, not from the model's own general knowledge, from that one string.
02 · WHY IT EXISTS

An assembled string is not an answer

Without this concept, Concept 07's 954-token string would just sit there. Something has to turn it into a response: run it through the model, get a probability distribution over the next token, choose one, append it, and repeat until the model decides to stop. That loop, plus the final citation attachment, is this concept.

03 · CONCRETE EXAMPLE

Same question, two different evidence realities

The query, continued from Concept 06/07, is "What is the return window after the grace period?" The evidence set includes c007's child chunk -- the exact grace-period sentence, per Module 07 Concept 06, but one that concept already flagged as liable to be cut mid-sentence without enough overlap. If the number survived the cut, the model can decode "14" truthfully. If it didn't, decoding "14" anyway would be a hallucination, not a grounded answer -- the same instructions and the same evidence-set label, two very different honest outcomes.

04 · TECHNICAL MECHANISM

Logits, softmax, argmax, repeat

At each position, the model produces one logit per vocabulary token (Module 02 Concept 05). Softmax turns those logits into a probability distribution that sums to 1. Greedy decoding picks the highest-probability token (argmax); the chosen token is appended and the whole string -- prompt plus everything generated so far -- is fed back in for the next position. This repeats until a stop token or length limit ends it.

06 · IMPORTANT DISTINCTIONS

"Grounded" describes the prompt, not the model's intent

A model doesn't "decide" to hallucinate or "decide" to ground itself -- it always just decodes the highest-probability continuation of whatever string it was actually given. Whether that continuation happens to match reality depends entirely on whether the true answer was in the string. Module 03 Concept 04 already stated this precisely: grounding reduces hallucination risk, it does not eliminate it -- this concept is the exact mechanical reason why.

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"If the answer is true, a well-instructed model will say it."

Only if the true answer's text actually survived into the assembled prompt. A model instructed to "answer only from the evidence" still has no way to state a fact that was never in the evidence -- correct behavior there is declining, not guessing correctly by luck.

"Citing a source means the claim came from that source."

Not automatically -- a citation tag can be attached to a hallucinated claim just as easily as a grounded one. Section 13's read-back check exists precisely because the citation and the claim have to be verified together, not trusted on sight.

06
MECHANISM

Why the same prompt can decode two honest ways

Module 02 Concept 09 already established that hallucination is a mechanical consequence of the decoding loop, not a separate malfunction: the model always decodes some continuation, whether or not that continuation is true. Module 03 Concept 04 already stated the resulting guarantee precisely -- grounding reduces hallucination risk, it does not eliminate it. This concept's own worked example (Sections 09-12) is the mechanical reason why: if the number "14" is textually present at the decoding position, its logit is high because the model is directly copying/attending to context it can see; if the text was cut before the number, there is nothing in the prompt to raise that logit, and a well-instructed model's highest logit shifts to an honest refusal token instead. A poorly instructed model, in the same cut-text case, can still assign a high logit to a plausible number anyway -- that is exactly the hallucination risk grounding reduces without eliminating.

07
MECHANISM

Stopping the loop

Generation stops when the model decodes a designated stop token, or when a maximum output-length limit is hit -- the same 512-token generation reserve Concept 07 already carved out of the 4,096-token context window in its own worked example. Nothing about that reserve is recomputed here; it is the ceiling this concept's output has to fit inside.

08
IMPORTANT DISTINCTIONS

Argmax is one decoding strategy, not the only one

Greedy/argmax decoding, used throughout this concept's own worked example for a single, hand-checkable path, always picks the single highest-probability token. Sampling strategies (temperature, top-k, top-p/nucleus) instead draw from the distribution, trading determinism for variety. This concept intentionally uses only argmax so the worked numbers below have one unambiguous winner to verify -- it does not claim argmax is how every production system decodes.

CODE

The softmax function, verified

JAVASCRIPT · SOFTMAX (also the lab's own code) 
function softmax(logits) {
  const keys = Object.keys(logits);
  const vals = keys.map(k => logits[k]);
  const max = Math.max(...vals);
  const exps = keys.map(k => Math.exp(logits[k] - max));
  const sum = exps.reduce((a, b) => a + b, 0);
  return Object.fromEntries(keys.map((k, i) => [k, exps[i] / sum]));
}

13
EVIDENCE + CONTROL

Citation attachment is a separate, checkable step

Once decoding stops, the pipeline attaches a [SOURCE n] tag identifying which evidence chunk a claim is being attributed to -- Concept 07's own boundary-tag scheme, reused here at the output side instead of the input side. Attaching the tag is mechanical and cheap; it is not, by itself, proof the claim is supported. The check that matters is whether the cited chunk's actual text contains what the claim states -- in the intact scenario, c007's child literally contains "14 days from the ship date," so [SOURCE 2] is a true citation. In the cut scenario, no chunk in the evidence set states a number at all, so the honest output attaches no numeric citation and says so plainly instead.

14
CONCRETE USE

The read-back guarantee this concept produces

The guarantee this concept can actually offer is narrow and precise: a claim is grounded if and only if its supporting text is present in the exact string decoded, and that presence is independently checkable by string-searching the cited chunk -- not by trusting the citation tag. This is the same "in the corpus" vs. "in the prompt" line Concept 07 already drew for evidence selection, now extended one step further to the generated output itself.

Misconceptions

Incorrect beliefCorrection

22
CAREER PRACTICE

Interview questions

Conceptual: why can the same instructions and the same evidence-set label produce two different honest answers?
Because "honest" is defined relative to what text actually survived into the assembled prompt, not relative to the label on the evidence set. If the supporting text didn't make it in (e.g. cut mid-chunk), decoding the true fact anyway would be a hallucination, not a correct grounded answer -- declining is the honest output in that case.
System design: a production RAG system's answers cite a source for every claim, yet an audit finds several citations don't actually support their claims. What's the likely fix?
The pipeline is almost certainly attaching citation tags mechanically (per the model's own claimed attribution) without verifying the cited chunk's text actually contains the claim -- add a read-back/string-match check between the generated claim and the cited chunk before the answer ships.
