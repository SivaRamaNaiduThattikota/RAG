01 · CONCEPT FIRST

Scalar, vector, matrix — one number, an ordered list, a grid

SCALAR

A single number on its own, e.g. 0.82. No components, no order to keep track of — just a magnitude.

VECTOR

An ordered list of numbers, e.g. (0.82, -0.14, 0.05). Order matters: position 1 always means the same thing every time this kind of vector appears.

VECTOR, AGAIN

Three numbers, one fixed order — a single row of a table, or a single point plotted using each number as one coordinate.

MATRIX

A rectangular grid of numbers arranged in rows and columns — several vectors of the same length, stacked so each row is one vector and each column keeps one position's meaning consistent down every row.

First memory: a scalar is one number, a vector is an ordered list of numbers, and a matrix is a grid of numbers — many same-length vectors stacked into rows. Order and position carry meaning; nothing here yet measures how "big" a vector is.
02 · WHY IT EXISTS

Concept 06 used the word "vector" without ever defining it

Module 03's nine-box skeleton drew a "Vectors" node and a "vector database" beside it, and moved on — the diagram needed the word before Module 04 existed to define it properly. Before this course can build a norm, a dot product, or a distance function on top of "vector," everyone needs the exact same starting definition, the same notation, and the same way of describing a grid's shape.

WITHOUT THIS DEFINITION

"Vector" stays an unexamined word borrowed from Concept 06's diagram — useful for pointing at a box, useless for writing an equation on top of it.

WITH THIS DEFINITION

Scalar, vector, and matrix each have a precise meaning and notation, so Concepts 02 through 10 can define operations on them without re-explaining what they are every time.

03 · CONCRETE EXAMPLE

Three toy scores per document — not an embedding yet

Suppose a search feature ranks documents using three hand-picked, placeholder scores per document: how fresh it is, how well its length fits the query, and how well its topic matches. These are toy numbers chosen for this example, not the learned numbers Module 08 will eventually produce.

DOCUMENT A

(0.90, 0.40, 0.70) — a vector: freshness 0.90, length-fit 0.40, topic-match 0.70, in that fixed order.

DOCUMENT B

(0.20, 0.95, 0.55) — a different vector, same three positions meaning the same three things.

DOCUMENT C

(0.60, 0.60, 0.10) — a third vector, still freshness, then length-fit, then topic-match.

ALL THREE STACKED

A 3 × 3 matrix: one row per document, one column per score, with column 1 always meaning "freshness" no matter which row you read.

Module 08 replaces these three hand-picked numbers with hundreds of learned numbers per document — an embedding is still just a vector, only longer and produced by a model instead of chosen by hand. That's a name to recognize for later, not a mechanism to learn today.

04 · TECHNICAL MECHANISM

Notation for all three, and how a matrix's shape is written

SCALAR

Plain lowercase, e.g. s or a

Written like an ordinary variable: s = 0.82. No index, because there's nothing inside it to point at.

VECTOR

Bold lowercase, components indexed

Written v = (v₁, v₂, v₃), read "v-one, v-two, v-three." vᵢ means "the number sitting in position i" — Document A's v₂ is 0.40.

MATRIX

Bold uppercase, entries indexed by row and column

Written M, with Mᵢ,ⱼ meaning "the number in row i, column j." Document B's freshness score is M₂,₁.

SHAPE

Rows × columns

Section 03's stacked matrix is "3 × 3" — 3 rows (documents), 3 columns (scores). Shape is always stated rows first, columns second.

06 · IMPORTANT DISTINCTIONS

Where a plain programming list and a mathematical vector diverge

ThisIs notBecause
A vectorAny list of numbers in codeA vector's positions have a fixed, shared meaning across every vector it gets compared to; a plain list promises nothing about what position 1 means from one list to the next
A row vectorA column vectorSame numbers, different orientation — shape 1 × n laid out sideways versus shape n × 1 laid out downward; which orientation is used is a bookkeeping choice, not a new kind of object
A 1 × n matrixA different object from a vectorA matrix with exactly one row behaves exactly like a row vector — "matrix" and "vector" overlap here, they aren't rivals
A scalarA one-component vectorA scalar has no components to index at all; a vector with one component, written (v₁), is still a vector with an index that happens to stop at 1
07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"The order of the numbers doesn't matter, only which numbers are present."

Section 03's Document A (0.90, 0.40, 0.70) and a rearranged (0.40, 0.90, 0.70) are different vectors — swapping positions swaps which score each number describes.

"A matrix is just several unrelated vectors sitting near each other."

A matrix's rows share the same column meanings — column 1 means "freshness" in every single row, not just the first one.

"A vector's 'size' means how large its numbers are."

That's next concept's job (the norm). Here, the only thing "size" can mean is how many components the vector holds — a separate idea this concept deliberately leaves unnamed until Concept 02.

"Vectors only exist in 2D or 3D, like arrows in physics."

Section 03's vectors have three components and nothing to do with physical space; a vector is just an ordered list, however many numbers it holds.

09 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

Three definitions

Scalar: one number. Vector: an ordered list of numbers. Matrix: a grid of numbers, rows and columns, many same-length vectors stacked.

Notation

s for a scalar; bold v with indexed components v₁…vₙ for a vector; bold M with Mᵢ,ⱼ for a matrix entry; shape written rows × columns.

Order and position are load-bearing

Swapping two components changes the vector; every row of a matrix must keep the same column meanings.

What stays deferred

Measuring a vector's length, comparing two vectors, and computing a distance are all still ahead — Concepts 02 through 04's job, not today's.

Teach-back questions

  1. Why is a 1 × n matrix effectively the same thing as a row vector?
  2. Why doesn't rearranging a vector's components produce "the same vector in a different order"?
  3. What's the one thing "size" can mean about a vector today, and what does it deliberately not yet mean?

04
INTUITION

A spreadsheet: one cell, one row, the whole sheet

A single spreadsheet cell holding one number is a scalar. One full row of that spreadsheet, read left to right in order, is a vector — the third cell in every row means the same column every time. The entire sheet, every row stacked under the last, is a matrix: rows and columns, with each column keeping one consistent meaning down its whole length.

Analogy boundaryA spreadsheet doesn't have a length, an angle, or a distance between two rows — those are exactly the ideas this analogy is not meant to carry. The point is only the structural claim: one number, an ordered row of numbers, a stack of same-shaped rows.

PRECISION

Formal definitions

TermDefinitionBoundary
ScalarA single number, with no components and no order to trackNot a one-component vector — a scalar has nothing to index
VectorAn ordered list of numbers, written v = (v₁, v₂, …, vₙ), where vᵢ is the number in position iHow many positions it has (n) is a count this concept deliberately leaves unnamed — Concept 02 names it "dimension"
MatrixA rectangular grid of numbers with entry Mᵢ,ⱼ in row i, column j, described by a shape of rows × columnsEquivalent to several same-length vectors stacked as rows (or columns) — not a fundamentally different object
Row vector / column vectorThe same list of numbers, oriented sideways (shape 1 × n) or downward (shape n × 1)A layout choice, not two different mathematical objects
06
MECHANISM

Tracing notation against Section 03's three documents

Document A — written v = (0.90, 0.40, 0.70). v₁ = 0.90, v₂ = 0.40, v₃ = 0.70. Three components, one fixed order.
Stacking rows — Document A becomes row 1, Document B row 2, Document C row 3 of a matrix M. M₁,₁ = 0.90 (row 1, column 1); M₂,₁ = 0.20 (row 2, column 1) — same column, same meaning, different row.
Reading the shape — three documents, three scores each, so M has shape 3 × 3 — 3 rows, 3 columns.

09
MATHEMATICS

Set notation for where these numbers live

A vector with n real-numbered components is written v ∈ ℝⁿ, read "v is an element of n-dimensional real space" — for now, just notation for "an ordered list of n real numbers," with the formal meaning of n itself still one concept away. A matrix with m rows and n columns is written M ∈ ℝ^(m×n).

v = (v₁, v₂, …, vₙ), v ∈ ℝⁿ M = [Mᵢ,ⱼ], M ∈ ℝ^(m×n)

Read each line as a definition, not a computation: the first says a vector is exactly its ordered list of components; the second says a matrix is exactly its grid of entries, indexed by row i and column j. Neither line computes anything about the vector or matrix's size — that's Concept 02.

11
CONCRETE USE

Four cards: a clean fit, a boundary case, a counterexample, and a mistake

CLEAN FIT

Section 03's three-score document table

Three fixed-meaning columns, one row per document — a textbook matrix, no edge cases.

BOUNDARY CASE

A vector with exactly one component, (0.5)

Still a vector by today's definition — a list of numbers doesn't stop being ordered just because it only has one entry. It is not, however, a scalar.

COUNTEREXAMPLE

An unordered set of tags, {"urgent", "billing"}

Not a vector — there's no fixed position for "urgent" to occupy across every document's tag set, so nothing here promises position 1 means the same thing twice.

MISTAKE TO AVOID

Stacking rows whose columns don't mean the same thing

If row 1's column 2 is "length-fit" but row 2's column 2 is accidentally "topic-match," the result isn't a valid matrix in this concept's sense, even though it still looks like a grid of numbers.

12
CODE

Scalars, vectors and matrices as plain nested lists

PYTHON · INDEXING A VECTOR AND A MATRIX, NO LIBRARIES 
def vector_component(v, i):
    # Section 05's v_i -- i is 1-indexed to match the lesson's notation
    return v[i - 1]

def matrix_entry(M, i, j):
    # Section 05's M_i,j -- row i, column j, both 1-indexed
    return M[i - 1][j - 1]

def matrix_shape(M):
    rows = len(M)
    cols = len(M[0]) if rows else 0
    return rows, cols

def extract_row(M, i):
    # Row i of a matrix, returned as its own standalone vector
    return list(M[i - 1])


# Section 03's three documents, stacked as Section 06 describes
scores = [
    [0.90, 0.40, 0.70],  # Document A
    [0.20, 0.95, 0.55],  # Document B
    [0.60, 0.60, 0.10],  # Document C
]

print(matrix_shape(scores))            # (3, 3)
print(matrix_entry(scores, 1, 1))      # 0.9
print(matrix_entry(scores, 2, 2))      # 0.95
print(extract_row(scores, 2))          # [0.2, 0.95, 0.55]

assert matrix_shape(scores) == (3, 3)
assert extract_row(scores, 2) == scores[1]

ECOSYSTEM

Where production code holds the same three ideas

NumPy's np.array([0.9, 0.4, 0.7]) is a vector by today's definition, and its .shape attribute reports exactly the rows-and-columns shape Section 05 defines, computed instead of hand-counted. A NumPy 2D array is a matrix the same way — np.array(scores).shape on Section 03's table returns (3, 3), matching Section 10's worked shape. Module 10 will introduce Oracle AI Database's VECTOR column type, which stores exactly this kind of ordered list of numbers as a native database type — named here only as a forward pointer, not explained until that module.

16
DIAGNOSIS

Failure modes — of the definitions themselves

OFF-BY-ONE

Confusing 1-indexed notation with 0-indexed code

Section 12's vector_component deliberately subtracts 1 so the lesson's v₁ notation and Python's list indexing agree — forgetting that conversion is the most common source of silent bugs here.

SHAPE MISMATCH

Stacking rows of different lengths

A "matrix" built from a 3-number row and a 4-number row isn't a valid matrix by today's definition — every row must share the same length before it counts as one grid.

MEANING DRIFT

Column i meaning different things in different rows

Section 11's mistake card generalizes: a matrix's usefulness depends entirely on every row agreeing what each column position means.

ORIENTATION SWAP

Transposing rows and columns without noticing

Reading a matrix as though its rows were columns silently swaps which axis is "documents" and which is "scores" — the numbers don't change, but every downstream lookup does.

18
REALITY

Production implications, at introductory depth

  • Every column in a stored matrix (a database table's numeric columns, for instance) needs a documented, stable meaning — Section 16's meaning-drift failure is a real migration risk if a column's definition quietly changes over time.
  • Row length must be enforced consistently before storage; a system that silently accepts rows of different lengths has already broken today's definition of a matrix, even if nothing crashes immediately.
  • Array libraries (Section 13) hide indexing cost behind convenient syntax — worth knowing the by-hand version exists underneath, for debugging when the convenient syntax returns something unexpected.

RECALL

Knowledge check

Define scalar, vector, and matrix in one sentence each.
Scalar: a single number. Vector: an ordered list of numbers. Matrix: a rectangular grid of numbers, equivalent to several same-length vectors stacked as rows.
Why is a 1 × n matrix not a fundamentally different object from a row vector?
A matrix with exactly one row is, entry for entry, the same ordered list of numbers as a row vector of the same length — "matrix" and "vector" overlap rather than compete here.
What does this concept deliberately not name, even though it's closely related to a vector's component count?
"Dimension." The count of components is real and used in today's notation (n in v ∈ ℝⁿ), but it isn't given the formal name "dimension" until Concept 02.

CAREER PRACTICE

Interview questions

A junior engineer says "a vector is just an array." What's missing from that description?
An array in code makes no promise about what each position means across different arrays; a vector's positions carry a fixed, shared meaning wherever it's compared to another vector of the same kind — the array is the storage, the fixed meaning per position is what makes it a vector.
Why must every row of a matrix have the same length before it's a valid matrix?
A matrix's shape (rows × columns) only makes sense if every row has the same column count; rows of different lengths break the grid structure the definition depends on, even before any operation is attempted on it.
Design question: a teammate proposes storing embeddings as unordered JSON objects (key-value pairs) instead of ordered arrays. What breaks?
Nothing guarantees a stable position-to-meaning mapping across different objects' keys the way an ordered vector's fixed component order does; any later operation that assumes "position i means the same thing in every vector" (which every later concept in this module will) has no guarantee left to rely on.
