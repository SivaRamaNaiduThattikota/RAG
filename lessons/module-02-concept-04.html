01 · CONCEPT FIRST

Query, key, value — and the order problem

For every position, self-attention produces three vectors from the same input: a query (what this position is looking for), a key (what every position offers to be matched against), and a value (what a position actually contributes once matched). A position’s new representation is a weighted sum of every position’s value, where the weights come from comparing its query against every key.

This weighted-sum computation treats the sequence as a set, not a sequence — nothing in it depends on which position came before another. Positional information is added into the input before attention runs specifically to repair that gap.

First memory: attention decides relevance; position has to be told to it separately.
02 · WHY IT EXISTS

Generality and order-blindness are the same trade-off

Concept 03 motivated self-attention as letting every position see every other position directly, computed in parallel. That is exactly what removes any built-in notion of order: a mechanism that treats every pair of positions symmetrically has no way to distinguish “A then B” from “B then A” unless something outside the comparison itself carries that information.

WHAT SELF-ATTENTION SOLVES

Which positions are relevant to which, regardless of distance between them.

WHAT IT DOES NOT SOLVE

Which position came first. That is positional information’s job alone.

03 · CONCRETE EXAMPLE

Resolving “it,” one query at a time

In “The trophy didn’t fit in the suitcase because it was too big,” the position holding it produces a query. That query is compared against the key of every other position. trophy and suitcase score higher than the or because; softmax turns those scores into weights that sum to one; the new representation for it becomes a weighted blend of every position’s value, dominated by trophy and suitcase.

QUERY

it asks: which positions are relevant to me?

SCORES → WEIGHTS

trophy, suitcase score highest; softmax normalizes.

MISSING PIECE

Nothing above used the fact that it comes after suitcase.

04 · TECHNICAL MECHANISM

The six moving pieces

QUERY

What I’m looking for

One learned projection of a position’s input vector.

KEY

What I offer to be matched

A second, separately learned projection of the same input vector.

VALUE

What I contribute if picked

A third learned projection — what actually gets blended into the output.

SCORE

Query · key similarity

A dot product between one query and one key, before any normalization.

SOFTMAX WEIGHT

Normalized relevance

Scores turned into positive weights that sum to one across all positions.

WEIGHTED SUM

The actual output

Every position’s value, combined according to its weight.

06 · IMPORTANT DISTINCTIONS

Terms that collapse into “attention”

Term What it actually is Common confusion
Score Raw query·key dot product Confused with the final attention weight
Weight Softmax-normalized score Confused with the value being combined
Positional encoding Order information added at the input Assumed to be part of the attention computation itself
Attention “query” A learned vector used inside one attention computation Confused with a RAG retrieval query — same word, unrelated mechanism

That last row matters specifically in this course: “query” means something entirely different when Module 03 starts discussing retrieval than it does here.

07 · COMMON MISTAKES

What beginners often misunderstand

“Attention already knows word order.”

The weighted-sum computation is identical regardless of position order unless positional information was added first.

“Query, key and value are three different kinds of tokens.”

They are three learned projections of the exact same input vector.

“The softmax weights are the attention mechanism’s output.”

The weights are an intermediate step; the actual output is the weighted sum of values.

“Positional encoding is a minor implementation detail.”

Without it, shuffling a sentence’s words would not change the model’s attention weights at all.

“An attention query is the same thing as a search query.”

They share a name and a rough “what am I looking for” intuition, not a mechanism.

“More attention heads means more attention to word order.”

Multiple heads (previewed, not taught here) give multiple relevance perspectives — none of them add order on their own.

08 · YOUR PROJECT MAPPING

Where this lands in Oracle RAG

PROMPT ORDER MATTERS System, context, and question all carry positional encoding

Where retrieved evidence sits in the assembled prompt is not invisible to the model — position is encoded into every token.

TWO DIFFERENT “QUERIES” Keep retrieval queries and attention queries mentally separate

A user’s retrieval query selects which documents enter the prompt; attention queries then run inside the model on whatever tokens arrived.

LONG CONTEXT COST Attention cost grows with sequence length

A longer retrieved-context window means more query/key comparisons, not just more tokens to read.

ENCODER VS. DECODER, AGAIN Embedding models and the generator both use self-attention

The same query/key/value mechanism runs in both architecture families from Concept 03 — only the masking differs.

LangChain and LangGraph never expose query/key/value directly — they operate above this layer entirely. This mechanism runs the same way regardless of which orchestration framework calls the model.

04
INTUITION

A room where everyone asks, everyone answers

Picture every word in a sentence standing in a room holding up a question (its query) and a description of what it has to offer (its key). Every word compares its question against every other word’s description, and listens most closely to whoever’s description matches best — collecting a blend of what those best-matching words actually have to say (their values). Nobody in the room announces where they were standing in line before entering.

Analogy boundaryReal queries, keys, and values are learned numeric projections, not spoken questions or descriptions — the comparison is a dot product, not a conversation, and “standing in line” is exactly the ordering information this analogy shows getting lost.
05
PRECISION

Formal definitions

Term Definition Boundary
Query (Q) A learned linear projection of a position’s input, used to probe relevance Recomputed at every attention layer
Key (K) A learned linear projection of a position’s input, compared against queries Same input as the query, different learned weights
Value (V) A learned linear projection of a position’s input, combined by weight What actually appears in the output, not the comparison
Positional encoding A fixed or learned vector added to a token embedding, indexed by position Added before the first attention computation, not recomputed per layer
06
MECHANISM

Two separate traces: attention, and position

SELF-ATTENTION, PER BLOCK
Project input into Q, K and V
Compute Q·K score for every pair of positions
Scale scores, then apply softmax per query
Take the weighted sum of V using those weights
POSITIONAL ENCODING, ONCE
Take each position’s index (0, 1, 2, …)
Compute a fixed or learned vector for that index
Add it to the token embedding
Feed the combined vector into block 1

Positional encoding runs once, before block 1. Self-attention’s query/key/value computation runs fresh inside every block in the stack.

08
ARCHITECTURE

Position enters once; attention repeats everywhere

Prompt tokens ↓ Embedding lookup ↓ + positional encoding (once) ↓ Self-attention (every block) ↓ Feed-forward (every block) ↓ Output head → decoding

Whether the tokens came from a system instruction, retrieved evidence, or the user’s question, they all pass through this identical positional-encoding-then-attention path — nothing about RAG changes this mechanism, it only changes which tokens arrive at the input.

09
MATHEMATICS

Scaled dot-product attention and sinusoidal position

$$\text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

Q, K, and V are matrices whose rows are per-position vectors; d_k is the key dimension. Dividing by √d_k before softmax keeps scores from growing so large that softmax saturates into near one-hot weights, which would starve gradient flow during training.

$$PE(pos, 2i) = \sin\left(\frac{pos}{10000^{2i/d}}\right), \quad PE(pos, 2i+1) = \cos\left(\frac{pos}{10000^{2i/d}}\right)$$

The original sinusoidal encoding assigns each position a vector built from sine and cosine waves at different frequencies, indexed by dimension i out of total dimension d — different frequencies let relative distances between positions be recovered from the encoding, not just absolute position.

10
WORKED EXAMPLE

Three positions, by hand

Three toy 2-dimensional vectors act as both keys and values: k1=[1,0], k2=[0,1], k3=[1,1], with matching values v1=[10,0], v2=[0,10], v3=[5,5]. Query q=[1,0.5].

scores: q·k1=1, q·k2=0.5, q·k3=1.5 (d_k=2, so divide by √2≈1.414)
scaled: [0.707, 0.354, 1.061] → softmax ≈ [0.32, 0.23, 0.45]
weighted sum ≈ 0.32·[10,0] + 0.23·[0,10] + 0.45·[5,5] = [5.45, 4.55]

The output [5.45, 4.55] leans slightly toward v1 and v3, matching that k3 scored highest and k1 second — exactly what the weights predict, with no reference anywhere to which position came first.

Trained per position

12
CODE

Scaled dot-product attention, from scratch

PYTHON · NUMPY-STYLE PSEUDOCODE 
import numpy as np

def softmax(x, axis=-1):
    x = x - np.max(x, axis=axis, keepdims=True)
    exp = np.exp(x)
    return exp / np.sum(exp, axis=axis, keepdims=True)

def attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)      # (n_queries, n_keys)
    weights = softmax(scores, axis=-1)   # each row sums to 1
    return weights @ V                   # (n_queries, d_v)

def sinusoidal_positions(seq_len, d):
    pos = np.arange(seq_len)[:, None]
    i = np.arange(d)[None, :]
    angle = pos / (10000 ** (2 * (i // 2) / d))
    pe = np.zeros((seq_len, d))
    pe[:, 0::2] = np.sin(angle[:, 0::2])
    pe[:, 1::2] = np.cos(angle[:, 1::2])
    return pe
13
ECOSYSTEM

What production LLMs actually use now

Production libraries implement this same computation with fused, hardware-optimized kernels rather than the naive matrix form above. Many current LLMs have also moved past both fixed sinusoidal and simple learned positional embeddings toward rotary position embeddings (RoPE), which rotate query and key vectors by an angle proportional to position — giving attention scores a built-in, mathematically clean sense of relative distance that extends more gracefully to longer sequences than the original schemes.

16
DIAGNOSIS

Failure modes

MISSING POSITION

Order-blind output

Omitting positional encoding makes permuted inputs indistinguishable to attention.

SCALING OMITTED

Softmax saturation

Skipping the √d_k scale can push softmax toward near one-hot weights and starve gradients.

ATTENTION COLLAPSE

Degenerate weighting

Nearly all weight concentrating on one position, reducing effective context use.

Q/K SWAP BUGS

Implementation error

Swapping query and key projections silently changes which side asks and which side answers.

LENGTH EXTRAPOLATION

Beyond trained context

Fixed schemes can degrade past the sequence lengths seen during training.

CROSS-ATTENTION MISWIRING

Wrong source sequence

Feeding keys/values from the wrong sequence in an encoder-decoder model.

CORRECTION

Misconceptions

Incorrect belief Correction
Attention inherently understands sequence order It computes an order-blind weighted sum; order comes only from positional information added beforehand.
Query, key, and value are different token types They are three learned projections of the same input vector.

18
REALITY

Production implications

  • Attention cost and memory grow quadratically with sequence length — a direct driver of long-context serving cost.
  • Positional-encoding choice affects how gracefully a model handles sequences longer than it was trained on.
  • RoPE and similar relative-position schemes are common in current production LLMs specifically for length generalization.
  • Verify the √d_k scaling and masking are implemented correctly — both are easy, silent bugs.
  • Multi-head attention (previewed here) adds parallel compute cost in exchange for multiple relevance perspectives.
  • Never assume a framework’s default positional scheme matches the one a specific pretrained model actually used.
19
RECALL

Knowledge check

What three vectors does self-attention compute per position, and what is each for?
Query (what this position seeks), key (what every position offers to be compared against), and value (what a position contributes once matched) — all three are learned projections of the same input.
Why divide attention scores by √d_k before softmax?
To keep the scores from growing large enough to push softmax toward near one-hot weights, which would hurt gradient flow during training.
Would scrambling a sentence’s word order change plain self-attention’s scores?
No — the score computation only depends on the query and key vectors present, not on their positions, unless positional information was added first.
Why is an attention “query” unrelated to a RAG retrieval query, despite the name?
An attention query is a learned vector used only inside one model’s forward pass to weight other positions; a retrieval query is a request compared against a document index — different mechanisms that happen to share a name.

FEEDBACK

Solution and teach-back

Open one worked reasoning pattern
Reordering the key/value pairs only relabels which row is which in the score and weight vectors — the query still produces the same set of scores against the same set of keys, so the weighted sum over the same values is identical. Order would only matter if a positional vector, tied to each pair’s position index, had been added into the keys or queries beforehand — at that point, the same key/value content in a different position would produce different scores.

PORTABLE MEMORY

Concept card

The mechanism

Attention(Q,K,V) = softmax(QKᵗ/√d_k)V. Query, key, value: three projections of one input. Position: added once, separately, before block 1.

Selection rule

  • No positional info → order-blind, always
  • Never skip the √d_k scale
  • Attention query ≠ retrieval query
  • RoPE for length generalization in production
23
CAREER PRACTICE

Interview questions

Derive, at a high level, why self-attention needs positional encoding but a feed-forward layer does not.
Self-attention computes a symmetric, order-blind comparison across all positions; a feed-forward layer only ever processes one position’s vector independently, so it never had a notion of cross-position order to lose in the first place.
What role does the √d_k scaling factor play mathematically?
It counteracts the growth in dot-product magnitude as dimensionality increases, keeping softmax inputs in a range where gradients remain informative rather than saturating.
Compare sinusoidal, learned, and rotary positional encodings.
Sinusoidal is a fixed formula with reasonable length generalization; learned embeddings are trained per position but generalize poorly past training length; rotary embeddings rotate query/key vectors by a position-dependent angle, giving strong relative-position behavior and better length generalization, which is why many current LLMs use it.
A colleague says “the retrieval query and the attention query are basically the same thing.” How do you respond?
They share a name and a loose “what am I looking for” intuition, but a retrieval query is compared against an external document index while an attention query is a learned vector compared against keys inside one model’s forward pass — conflating them causes real confusion when discussing a RAG system’s architecture.
