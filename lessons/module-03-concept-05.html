Parametric and
non-parametric memory.

Concept 04's grounding argument already leaned on a distinction it never named: evidence "physically in the prompt" versus whatever the model "remembers" from frozen weights. This concept names both sides formally — parametric memory, Module 02 Concept 09's lossy statistical residue baked into weights during pretraining, and non-parametric memory, the external, searchable corpus Concept 01 already called by name. 01 · CONCEPT FIRST

Two memory types, named for the first time

PARAMETRIC MEMORY

Module 02 Concept 09's lossy statistical residue, baked into the weights by pretraining's gradient. No read channel back to any specific fact — only a forward pass that activates weight groups shaped by everything the model ever saw.

NON-PARAMETRIC MEMORY

An external corpus — Concept 01's term — held as separate, inspectable text, searchable and editable at any time. Retrieval reads it directly; nothing has to be baked in first.

First memory: parametric memory is baked in and only changes by retraining; non-parametric memory is a corpus you can edit directly, any time.
02 · WHY IT EXISTS

Concept 04's distinction, finally given its real names

Concept 04 said grounding means evidence "physically in the prompt," contrasted against a model just "remembering" from frozen weights. Those two sides are exactly parametric and non-parametric memory — Concept 04 used the idea without the vocabulary. This concept supplies the vocabulary, and the one property — editability — that actually explains why RAG needs both.

WITHOUT THE NAMES

"Evidence in the prompt" versus "whatever the model remembers" — usable, but imprecise.

WITH THE NAMES

Non-parametric memory retrieved at query time, versus parametric memory baked in at training time — precise, and ready for Concept 06's pipeline breakdown.

03 · CONCRETE EXAMPLE

A headcount number, updated Tuesday

Oracle's internal headcount changes weekly. A model trained six months ago has some headcount number baked into its parametric memory — stale by definition, and there is no way to edit just that one fact without retraining the whole model. A non-parametric corpus document, "Company headcount: updated weekly," gets edited Tuesday, and a query on Wednesday retrieves the new number instantly. Same underlying fact, two completely different update stories.

PARAMETRIC PATH

Stale number, baked in since the last training run — fixing it means retraining or fine-tuning the whole model.

NON-PARAMETRIC PATH

Edit the corpus document directly — the very next query sees the update, with zero training involved.

04 · TECHNICAL MECHANISM

The same fact, stored two structurally different ways

WRITE COST

Retrain vs. edit a document

Parametric: an entire training run. Non-parametric: a direct edit to the corpus, no training involved.

READ MECHANISM

A forward pass vs. a retrieval query

Parametric: activates weight groups shaped by everything ever seen. Non-parametric: a search returns the specific passage.

FRESHNESS

Frozen at cutoff vs. current as of the last edit

Parametric memory's freshness is fixed at training time. Non-parametric memory's freshness is fixed at last edit time — which can be seconds ago.

WHAT NEITHER REPLACES

Language ability itself stays parametric

Non-parametric memory supplies facts to condition on; the generator still needs Module 02's parametric mechanism to read, reason, and produce fluent language at all.

05 · ARCHITECTURE / FLOW

Where each memory type actually lives in the RAG skeleton

Documents↓ Non-parametric corpus↓ Retrieval↓ Context↓ LLM — parametric memory inside↓ Answer

Non-parametric memory lives in the corpus, outside the model entirely — everything left of "Retrieval." Parametric memory lives inside the LLM box itself, unchanged from Module 02. RAG's whole shape is retrieving from the left side to condition generation on the right side — Concept 06 covers how the left side is actually built and queried; this concept only names what each side is.

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"RAG means the model no longer uses parametric memory."

False — the generator still relies on parametric memory for grammar, reasoning, and language ability; non-parametric memory only supplies additional facts to condition on.

"Updating the corpus updates the model."

False — a corpus edit changes what retrieval can find; it never touches a single weight.

"Non-parametric memory is just a bigger context window."

No — a context window holds whatever's currently in the prompt; non-parametric memory is the whole searchable corpus, only a retrieved slice of which ever reaches the prompt.

04
INTUITION

A memorized fact versus a sticky note on the fridge

A memorized fact is baked into how you think — updating it means genuinely relearning, slowly, through repeated exposure. A sticky note on the fridge is external and instantly editable — cross out yesterday's number, write today's, done. Parametric memory is the memorized fact; non-parametric memory is the sticky note.

Analogy boundaryA person can consciously decide to trust the sticky note over a shaky memory. A model has no equivalent judgment call built in by default — Concept 04's "silent override" failure mode is exactly a case where the model effectively ignores its own sticky note. The analogy conveys the update-cost asymmetry, not the model's actual behavior when the two memories conflict.

PRECISION

Formal definitions

TermDefinitionBoundary
Parametric memoryInformation encoded in a model's weights via pretraining's gradient — Module 02 Concept 09's lossy statistical residue.No read channel to any single fact; only a forward pass activating weight groups shaped by everything seen.
Non-parametric memoryInformation held as external, structured text — Concept 01's corpus — searchable and editable independent of any model weight.Requires a retrieval step to reach the model at all; nothing is "in" the model until retrieved.

MECHANISM

The same fact, traced through both memory types

A fact changes in the real world (e.g. Tuesday's headcount update)
Parametric path: the fact is not reflected anywhere until the next training run touches it — potentially months away
Non-parametric path: the corpus document is edited directly — the change is live immediately
A query arrives asking about the fact
Parametric-only generation answers from whatever residue was baked in at the last training cutoff — possibly stale
RAG's retrieval step reaches into non-parametric memory instead, returning the current document — the freshness asymmetry resolved in non-parametric memory's favor

09
MATHEMATICS

Freshness as a function of last-update time

Define t_now as the current time, t_train as a model's last training-data cutoff, and t_edit(d) as a corpus document d's last edit time.

Parametric freshness gap: t_now − t_train (grows every day between training runs, with no way to shrink it except retraining)
Non-parametric freshness gap: t_now − t_edit(d) (can be reset to ≈0 at any moment, by editing d)

The structural asymmetry: the parametric gap only grows, monotonically, until the next training run resets it. The non-parametric gap can be reset independently, document by document, at any time — this is what "editable" actually buys, made precise.

10
WORKED EXAMPLE

The headcount fact, dated

Model trained with data up to t_train = January 1. Corpus document "Company headcount" last edited t_edit = Tuesday (this week). Query arrives Wednesday (t_now).

Memory typeFreshness gapAnswer quality
Parametric onlyt_now − t_train ≈ several monthsWhatever headcount existed as of January 1 — likely stale
Non-parametric (retrieved)t_now − t_edit ≈ 1 dayTuesday's actual number

The parametric gap will not shrink until a new training run. The non-parametric gap resets to nearly zero the moment the document is edited — no retraining required at all.

Something like basic arithmetic barely benefits from retrieval — parametric memory already handles it reliably, echoing Concept 04's "2+2" counterexample.

COUNTEREXAMPLE

General reasoning ability

Not a "fact" retrieval can supply at all — this stays squarely parametric, retrieval or not.

A bigger model still only has parametric memory frozen at its own training cutoff — size doesn't buy freshness.

CODE

Two update paths, contrasted directly

PYTHON · UPDATE COST, PARAMETRIC VS. NON-PARAMETRIC 
# Non-parametric: a fact lives in an editable corpus dict.
# Updating it is O(1) -- no training loop involved at all.
corpus = {"headcount": {"value": 41_200, "last_edit": "2026-08-18"}}

def update_non_parametric(corpus, key, new_value, today):
    corpus[key] = {"value": new_value, "last_edit": today}
    # done -- the very next retrieval sees this immediately

update_non_parametric(corpus, "headcount", 41_350, "2026-08-19")
print(corpus["headcount"])  # {'value': 41350, 'last_edit': '2026-08-19'}

# function -- the ONLY path is retraining, illustrated as a stub
# to make the asymmetry explicit rather than implemented for real.
def update_parametric_requires_full_retrain(model_weights, training_corpus):
    # This is not a targeted edit -- it is an entire training run
    # over the whole corpus, which happens to also shift this one

ECOSYSTEM

Where this distinction shows up in the literature

Lewis et al. (2020) coined "parametric memory" and "non-parametric memory" as the exact pair this concept names — the original RAG paper's own framing. Petroni et al. (2019), the LAMA probe, empirically measures what parametric memory actually contains by querying language models like fill-in-the-blank knowledge bases. Khandelwal et al. (2020), kNN-LM, shows non-parametric memory can augment a parametric language model at inference time with zero retraining, by nearest-neighbor lookup over a datastore. Borgeaud et al. (2021), RETRO, scales the same non-parametric-memory idea to retrieval from trillions of tokens, still without retraining the underlying model for each new fact.

16
DIAGNOSIS

Failure modes

STALE-CORPUS ASSUMPTION

Believing an unedited corpus stays reliable forever

Non-parametric memory is only as fresh as its last edit — an unmaintained corpus can go stale exactly like parametric memory can.

RETRAIN-AVOIDANCE OVERREACH

Trying to solve every freshness problem with retrieval

Some things (general reasoning ability) simply aren't facts retrieval can supply — Section 11's counterexample.

SILENT OVERRIDE, REVISITED

Parametric memory winning when it shouldn't

Concept 04's silent-override failure is this concept's memory conflict made concrete: the model answers from parametric memory even with fresher non-parametric evidence retrieved.

18
REALITY

Production implications, at introductory depth

  • Track a corpus document's last-edit timestamp so staleness is measurable, not just assumed away.
  • Retraining cadence sets parametric memory's freshness floor — a fact that changes faster than the retrain schedule must live in the corpus.
  • An unmaintained corpus is its own risk: non-parametric memory's freshness advantage only holds if edits actually happen.

Pricing that changes quarterly should live in non-parametric memory — a corpus document editable the moment pricing changes, with the next query reflecting it immediately. Stored parametrically instead, the pricing fact would be frozen at whatever the last training run captured, and every quarterly change would require a full retrain just to stay current — an unworkable update cadence for a fact that changes this often.

23
CAREER PRACTICE

Interview questions

Explain parametric versus non-parametric memory to a non-technical stakeholder.
Parametric memory is like something the model memorized during training — hard to change without retraining it. Non-parametric memory is like a reference document it can look up — easy to edit any time, with the change visible immediately.
Why doesn't a larger model reduce the need for retrieval?
A larger model still only has parametric memory frozen at its own training cutoff — size doesn't add freshness, it just changes how much was memorized as of that cutoff.
Design question: a fact changes hourly. Which memory type, and what's the risk?
Non-parametric memory, necessarily — hourly changes are far faster than any realistic retraining cadence. The risk is corpus-edit latency and reliability: the non-parametric path only wins if the hourly edit actually happens on schedule.
