01 · CONCEPT FIRST

A block has exactly two sublayers

Token embeddings enter a stack of identical blocks. Each block runs two sublayers in order: self-attention, which lets every position gather information from every other position, and a feed-forward network, which transforms each position on its own, independently of every other position. Both sublayers are wrapped in a residual connection and a layer normalization step.

After the last block, an output head turns the final representations into the next-token distribution that Concept 07's decoding loop already knows how to consume.

First memory: attention mixes across positions; the feed-forward sublayer never does.
02 · WHY IT EXISTS

Why not process tokens one at a time, in order?

Earlier sequence models read a sentence one token at a time, carrying a running summary forward — slow to train, and prone to losing context from far earlier in a long sequence. The transformer's core move: let every position look at every other position directly, in one step, computed in parallel across the whole sequence, rather than passing information through a long chain.

OLDER SEQUENCE MODELS

Process one position at a time; long-range context has to survive a long relay chain.

TRANSFORMER BLOCKS

Every position can attend directly to every other position, computed in parallel.

03 · CONCRETE EXAMPLE

Resolving “it” across a stack of blocks

In “The trophy didn’t fit in the suitcase because it was too big,” the word it is ambiguous on its own. Self-attention lets the position holding it pull in information from trophy and suitcase directly. Across several blocks, that position’s representation keeps refining, layer by layer, until it carries enough context for the output head to eventually favor the correct reading. Exactly how attention decides how much to pull from each position is Concept 04’s job, not this one’s.

BLOCK 1

it’s representation starts gathering signal from nearby nouns.

BLOCK 2–3

Feed-forward sublayers further transform that gathered signal, position by position.

FINAL BLOCK

it’s representation is contextually rich enough for the output head to use.

04 · TECHNICAL MECHANISM

What sits inside the stack

EMBEDDING LAYER

Token ID → vector

Every token ID is looked up in an embedding table, exactly as Module 01 described.

POSITIONAL INFO

Previewed, not taught here

Attention alone cannot tell position order apart — Concept 04 covers how position gets added back in.

SELF-ATTENTION SUBLAYER

Mixes across positions

Lets each position gather context from every other position. Mechanics are Concept 04’s subject.

FEED-FORWARD SUBLAYER

Transforms one position at a time

The same small network applied independently to every position — no mixing across positions here.

RESIDUAL CONNECTIONS

Add the sublayer’s output back

Each sublayer’s output is added to its own input, rather than replacing it outright.

LAYER NORMALIZATION

Keeps activations well-scaled

Rescales values at each step so a deep stack of blocks trains stably.

05 · ARCHITECTURE / FLOW

Decoder-only is this course’s path

ENCODER-STYLE (BIDIRECTIONAL)

Every position can attend to every other position, including ones later in the sequence — common in embedding models.

DECODER-STYLE (CAUSAL)

A position can only attend to itself and earlier positions — required for the autoregressive generation loop from Concept 07.

Token IDs → Embedding lookup → + positional info → Block ×N → Output head → Next-token distribution

06 · IMPORTANT DISTINCTIONS

Terms that get flattened into “the transformer”

Term What it actually is Common confusion
Block One repeated unit containing both sublayers Confused with a single sublayer
Self-attention sublayer Mixes information across positions Assumed to be the model’s only real work
Feed-forward sublayer Transforms each position independently Overlooked despite often holding most parameters
Encoder vs. decoder Bidirectional context vs. causal, left-to-right-only context Assumed to be two names for the same thing

Two blocks in the same stack share an identical architecture, but never share learned parameters — each block’s attention and feed-forward weights are trained separately.

07 · COMMON MISTAKES

What beginners often misunderstand

“Attention is the whole block.”

The feed-forward sublayer runs every time too, and often holds the majority of a block’s parameters.

“Every block in the stack is architecturally different.”

Every block runs the identical two-sublayer pattern; only the learned weights differ.

“Residual connections are a minor optimization detail.”

Deep stacks reliably fail to train well without them — they are structural, not cosmetic.

“More blocks is always better.”

Depth trades directly against latency, memory, and training cost.

“Encoder and decoder transformers are interchangeable.”

A decoder’s causal masking is required for the generation loop; an encoder’s bidirectional context is not compatible with it.

“Positional information is part of attention itself.”

Self-attention alone is permutation-invariant — position has to be added separately, which Concept 04 covers.

08 · YOUR PROJECT MAPPING

Where the block stack lands in Oracle RAG

ONE STACK, ONE PASS System + context + question share the same blocks

There is no special-cased path for retrieved evidence — every part of the assembled prompt passes through the identical stack.

EMBEDDING MODEL VS. GENERATOR Often different architecture families

Embedding models commonly use encoder-style bidirectional blocks; the generator uses decoder-style causal blocks — two separate stacks, not one shared one.

STACK DEPTH AND COST More blocks means more latency and compute per request

Model size (block count and width) is a direct lever on response time and inference cost.

WHY DECODING NEEDS CAUSAL BLOCKS Generation must not see future tokens

Concept 07’s one-token-at-a-time loop only works because decoder blocks never attend to positions that don’t exist yet.

Nothing about retrieval, Oracle, or orchestration changes how the block stack itself runs — they only change what tokens arrive at its input.

04
INTUITION

An assembly line of identical stations

Picture an assembly line with N identical stations. At every station, each worker first huddles briefly with every other worker on the line to gather relevant context, then returns to their own desk to update their notes independently. The huddle is self-attention; the desk work is the feed-forward sublayer. Every station runs the same two-step routine, but each station’s workers have learned their own way of huddling and their own way of updating notes.

Analogy boundaryThe “huddle” is not a conversation — it is a weighted combination computed from learned projections of every position’s representation. Concept 04 replaces this analogy with the actual computation.
05
PRECISION

Formal definitions

Term Definition Boundary
Block One repetition containing a self-attention sublayer followed by a feed-forward sublayer Architecture is identical across blocks; learned parameters are not
Residual connection Adding a sublayer’s output back to the input that was fed into it Applied once per sublayer, twice per block
Layer normalization Rescaling a representation’s values to a stable range at a given point in the block Placement (before or after a sublayer) varies by implementation
Decoder-only / causal A block variant where each position may only attend to itself and earlier positions Required for the autoregressive loop in Concept 07; not a property of feed-forward sublayers
06
MECHANISM

One block, two sublayers, traced in order

Representations enter the block from the previous block (or from the embedding layer, for block 1)
Self-attention sublayer mixes information across every position
That sublayer’s output is added back to its input, then normalized
Feed-forward sublayer transforms each position independently
That sublayer’s output is added back to its input, then normalized
The result becomes the input to the next block, or to the output head if this was the last block

Nothing in this trace depends on knowing exactly how self-attention decides its mixing weights — that computation is a black box here on purpose, opened fully in Concept 04.

08
ARCHITECTURE

The whole assembled prompt shares one stack

System + retrieved context + question ↓ Tokenized (Concept 02) ↓ Embedding lookup ↓ Block ×N (this concept) ↓ Output head ↓ Decoding loop (Concept 07)

Retrieval, Oracle, and orchestration all finish their work before this diagram starts — by the time tokens reach the first block, the stack has no idea which of them came from a system instruction, a retrieved passage, or the user’s question. Anything that needs to shape how the model treats different parts of the prompt has to happen through the tokens and structure fed in, not through a special path inside the stack.

09
MATHEMATICS

Residual addition and the feed-forward sublayer

Block, pre-norm form: x' = x + Attention(Norm(x)); y = x' + FFN(Norm(x'))

x is the block’s input representation for one position; Attention(·) and FFN(·) are the two sublayers. Each is added back to the value it started from, rather than replacing it — this is the residual connection.

FFN(x) = W₂ · activation(W₁x + b₁) + b₂

The feed-forward sublayer is a small two-layer network applied with the same weights at every position — it has no mechanism to look at any other position, which is exactly what separates it from the attention sublayer above it.

10
WORKED EXAMPLE

Residual addition on one toy number

Let one position’s representation, simplified to a single number, be x = 2.0. Suppose a toy feed-forward sublayer computes FFN(x) = 0.5x + 1 (standing in for the real two-layer network).

FFN(2.0) = 0.5(2.0) + 1 = 2.0
With residual: y = x + FFN(x) = 2.0 + 2.0 = 4.0
Without residual: y = FFN(x) = 2.0 (the original 2.0 is gone entirely)

This toy example only illustrates residual addition on the feed-forward sublayer — the same addition happens around the attention sublayer too, using its real output in place of this toy FFN(x).

12
CODE

A block’s shape, attention left as a black box

PYTHON · FROM-SCRATCH PSEUDOCODE 
def transformer_block(x, self_attention, feed_forward, norm):
    # self_attention and feed_forward are functions supplied from outside;
    # their internals are Concept 04's subject, not this one's.
    x = x + self_attention(norm(x))   # attention sublayer + residual
    x = x + feed_forward(norm(x))     # feed-forward sublayer + residual
    return x

def transformer_stack(token_embeddings, blocks):
    x = token_embeddings
    for block in blocks:              # each block: its own learned weights
        x = block(x)
    return x                          # final representations -> output head

ECOSYSTEM

The same shape in production libraries

Hugging Face model classes such as a GPT-style decoder layer or a Llama-style decoder layer implement exactly this residual-wrapped, two-sublayer pattern, with a real self-attention implementation and a real feed-forward implementation in place of this lesson’s black boxes. Production implementations also add causal masking for decoder-style models and, at generation time, a key/value cache across decoding steps — previewed here, not covered until it is directly relevant to the decoding loop.

15
CONTRAST

Choosing an architecture family

Family Wins when Operational cost
Decoder-only (causal) Open-ended generation, one token at a time Cannot use future context even when available
Encoder-only (bidirectional) Producing one representation per input, e.g. an embedding Cannot generate a variable-length sequence token by token
Encoder-decoder A fixed input transformed into a different output sequence Two stacks to train and serve instead of one
16
DIAGNOSIS

Failure modes

TRAINING INSTABILITY

Missing or misplaced residuals

Deep stacks trained without residual connections routinely fail to converge.

NORM PLACEMENT

Pre-norm vs. post-norm sensitivity

Where normalization sits relative to a sublayer measurably affects training stability at scale.

ARCHITECTURE MISMATCH

Bidirectional model used for generation

An encoder-only model has no causal masking and cannot safely drive a decoding loop.

CAPACITY BLIND SPOT

Undersized feed-forward sublayer

Shrinking it to save parameters can remove more model capacity than expected.

DEPTH VS. COST

Over-deep stacks

Latency and memory scale with block count long before quality gains flatten out.

CAUSAL LEAK

Missing or incorrect masking

A decoder block that can attend to future positions breaks the entire generation guarantee.

17
CORRECTION

Misconceptions

Incorrect belief Correction
Self-attention is the only meaningful computation in a block The feed-forward sublayer runs every time too and often holds most of a block’s parameters
Blocks in a stack share learned weights Every block has its own independently learned attention and feed-forward parameters
Residual connections are a minor training trick They are structural — very deep stacks reliably fail to train well without them
Encoder and decoder blocks are the same thing used differently They share the two-sublayer pattern, but a decoder adds causal masking an encoder does not have
18
REALITY

Production implications

  • Block count and width are direct, measurable levers on latency, memory, and serving cost.
  • Confirm causal masking is correctly applied whenever a decoder-style model drives a generation loop.
  • Track normalization placement (pre-norm vs. post-norm) as an architecture decision, not an implementation detail.
  • Budget feed-forward sublayer width deliberately — it is not a safe place to cut parameters casually.
  • Key/value caching across decoding steps (previewed here) is what makes long generations tractable in production.
  • Match architecture family to task: bidirectional for one-shot representations, causal for open-ended generation.
19
RECALL

Knowledge check

What are the two sublayers inside every transformer block, in order?
Self-attention first, then a feed-forward network — each wrapped in a residual connection and a normalization step.
Why does the feed-forward sublayer not mix information across positions?
It applies the same small network independently to each position’s representation, with no mechanism to reference any other position.
What would likely happen to a 40-block stack trained without residual connections?
It would very likely fail to train well — residual connections are what let gradient signal and information survive being passed through that many layers.
Why must a decoding model’s blocks be causal?
Because the autoregressive generation loop produces tokens one at a time and must never attend to positions that don’t exist yet.

21
FEEDBACK

Solution and teach-back

Open one worked structural trace
Each of the 3 blocks runs self-attention first (with the block’s input added back via a residual connection and normalized), then the feed-forward sublayer second (with that sublayer’s output likewise added back and normalized) — identically in structure across all 3 blocks, differing only in learned weights. Positional information has to already be present in the representation before the very first block’s attention sublayer runs, since attention itself has no way to recover position afterward. An encoder-only model cannot replace the generator here because it lacks causal masking — every position could attend to every other position including ones later in the sequence, which is incompatible with generating tokens one at a time.

PORTABLE MEMORY

Concept card

The block

Self-attention (mixes positions) → residual + norm → feed-forward (per-position) → residual + norm. Repeated N times, own weights each time.

Selection rule

  • Generation needs causal (decoder) blocks
  • One-shot representation needs bidirectional (encoder) blocks
  • Never drop residual connections in a deep stack
  • Attention’s own mechanics: Concept 04
23
CAREER PRACTICE

Interview questions

Walk through what happens inside one transformer block, in order.
Self-attention mixes context across positions, its output is added back to the block’s input and normalized; then the feed-forward sublayer transforms each position independently, and its output is likewise added back and normalized.
Why are residual connections considered essential rather than optional in deep transformer stacks?
They let each sublayer learn a refinement added to its input rather than a full replacement, which keeps gradients and information flowing through very deep stacks that would otherwise be difficult to train.
What distinguishes an encoder-style block from a decoder-style block?
A decoder-style block adds causal masking so a position can only attend to itself and earlier positions; an encoder-style block allows full bidirectional attention.
Where does most of a transformer block’s parameter count typically live?
Often in the feed-forward sublayer’s weight matrices, not solely in the attention sublayer — a commonly underestimated point.
System design: you need a single model to both embed documents and generate answers. What architecture consideration follows?
These are usually two separate models with different block families — an encoder-style model for embeddings and a decoder-style model for generation — rather than one shared stack.
