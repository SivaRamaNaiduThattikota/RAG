MODULE 08 · CONCEPT 05

Not just a negative.
The right kind of wrong answer.

Concept 04 proved that pulling toward a positive and pushing away from a negative lowers a real, grounded contrastive loss -- but it never asked which negative is worth pushing away from. This concept names three categories precisely: a positive pair (query plus a document known to be relevant), an easy or random negative (any unrelated document, already trivially far away), and a hard negative (topically or lexically similar to the positive, but not actually relevant). On Module 07 Concept 09's own frozen Solstice/Cobalt vectors, a hard negative tied exactly with the positive at cosine 0.6644 produces a loss 409,007 times larger than an easy negative's loss at the real production temperature -- proof that the same fixed loss formula can teach almost nothing, or almost everything, depending purely on which negative it's handed.

01 · CONCEPT FIRST

Three categories, precisely defined

THIS CONCEPT

A positive pair is a query plus a document known to be relevant (from human relevance judgments or naturally paired data, like a resolved support ticket). An easy (or random) negative is any unrelated document, already trivially far away. A hard negative is topically or lexically similar to the positive but NOT actually relevant -- it's what makes the SAME loss formula (Concept 04, cited) actually have something to teach.

NOT THIS CONCEPT

The actual algorithms for mining hard negatives at scale (BM25/ANN mining, Module 24, named forward only); pooling, embedding dimensions and normalization (Concept 06, named forward only).

First memory: an easy negative is already far away; a hard negative is close enough that pushing it away actually teaches something.
02 · WHY IT EXISTS

A fixed loss can already have nothing left to learn from

Concept 04's loss can be computed on real vectors -- but if the negative fed into it is already trivially far away, the loss (and the training signal it carries) is already close to zero, even before training starts. At the real production temperature, an easy negative's loss comes out to 1.69×10⁻⁶ nats -- next to nothing left for gradient descent to correct.

03 · CONCRETE EXAMPLE

Solstice, Cobalt, and a tie that IS a hard negative

Reusing Module 07 Concept 09's own frozen vectors, unchanged: query about Solstice Cloud's refund policy. Positive = S1, Solstice's own refund clause (cosine 0.6644). Hard negative = B1, Cobalt's near-identical refund clause differing only in a numeral this toy model can't see (cosine 0.6644 -- an EXACT tie with the positive). Easy negative = B2, Cobalt's unrelated invoicing clause (cosine 0.0000, trivially far away).

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"More negatives always beats better negatives."

False -- DPR's own ablation: 127 in-batch gold negatives alone reach 55.8% Top-5; adding just ONE hard negative lifts that to 65.8% (+17.92% relative). A second added hard negative barely moves it further.

"The highest-scoring unlabeled candidate is always a safe negative."

False -- it might be a false negative: actually relevant, just unlabeled. Mining aggressively for hard negatives specifically raises this risk, since it deliberately searches the exact similarity region a true positive would also occupy.

"This lesson teaches how to mine hard negatives."

False -- it only defines the categories and shows why the choice matters. The actual mining algorithms (BM25/ANN-based) are Module 24's job.

04
INTUITION

The trick option vs. the obviously wrong one

A hard negative is the multiple-choice trick option built to look almost right. An easy negative is the option so obviously wrong that avoiding it teaches nothing at all.

Analogy boundaryThe multiple-choice picture explains why hard negatives teach more. It doesn't capture the false-negative risk or the softmax's simultaneous handling of many negatives at once -- Sections 09/16 state those precisely.

06
MECHANISM

Gap drives the loss, regardless of which category produced it

Reducing Concept 04's grounded loss to exactly one positive and one negative (the boundary case Concept 04 Section 11 already named): gap = cos_pos − cos_neg; prob_pos = sigmoid(gap/τ); Loss = softplus(−gap/τ) -- algebraically identical to Concept 04's numerator/denominator form, checked to match on every row below. A hard negative produces a small gap (by definition); an easy negative produces a large one. The loss responds to the GAP, not to either cosine value alone.

08
ARCHITECTURE

One loss, many possible negative sources

IN-BATCH (FREE)

Other documents already in the same training batch become negatives at no extra cost -- M04C08's own term. Not automatically hard; just whatever happens to share a batch.

MINED (DELIBERATE)

A separate retrieval pass (BM25/ANN, Module 24, named forward only) deliberately searches for candidates similar to the positive -- raising both teaching value AND false-negative risk together.

09
MATHEMATICS

The softplus/sigmoid form, verified against Concept 04's own numerator/denominator argument

gap = cos_pos − cos_neg
prob_pos = sigmoid(gap/τ) = 1/(1+e^(−gap/τ))
Loss = −log(prob_pos) = softplus(−gap/τ)

At gap=0 (a tied hard negative), prob_pos=0.5000 at ANY temperature -- scaling a zero gap changes nothing, so the tied case is tau-invariant. As gap grows (an easier negative), prob_pos→1 and Loss→0 far more sharply at a small τ than at τ=1. Deriving dL/dq remains out of scope, cited from Concept 04, not reopened here.

12
CODE

The 2×2×τ matrix, from scratch

PYTHON · REUSES CONCEPT 04'S infonce_loss UNCHANGED 
import math

def infonce_loss(cos_pos, cos_neg, tau):
    e_pos = math.exp(cos_pos / tau)
    e_neg = math.exp(cos_neg / tau)
    return -math.log(e_pos / (e_pos + e_neg))

# Frozen -- Module 07 Concept 09's own already-verified cosines.
S1, B1_HARD, B2_EASY, S1_SHARP = 0.6644, 0.6644, 0.0000, 0.9759

assert round(infonce_loss(S1, B1_HARD, 0.05), 6) == 0.693147
assert round(infonce_loss(S1, B2_EASY, 0.05), 12) == round(1.694707e-6, 12)
assert round(infonce_loss(S1_SHARP, B1_HARD, 0.05), 6) == 0.001968

ratio = infonce_loss(S1, B1_HARD, 0.05) / infonce_loss(S1, B2_EASY, 0.05)
assert round(ratio) == 409007

ECOSYSTEM

Where "hard negative" comes from, and the real mining tool

Karpukhin et al. (2020), Dense Passage Retrieval (DPR), Section 3.2, defines this concept's exact three negative types verbatim: Random / BM25 (their own term for hard negatives) / Gold. Table 3 (NQ dev set) gives the real ablation cited in Section 10: 127 in-batch gold negatives alone reach 55.8/73.0/83.1% Top-5/20/100; adding one BM25 hard negative reaches 65.8/78.0/84.9%; a second does not help further. sentence-transformers' hard-negatives-mining docs give this concept's exact soft/easy-vs-hard terminology and name the real mine_hard_negatives() utility. MultipleNegativesRankingLoss documentation (reused from Concept 04) grounds the τ=0.05 production default and the fact that plain in-batch negatives are not automatically hard.

RECALL

Knowledge check

Define all three negative-related terms.
Positive pair: query plus a known-relevant document. Easy/random negative: any unrelated document, already trivially far away. Hard negative: topically/lexically similar to the positive but not actually relevant.
Why is gap=0 tau-invariant?
prob_pos = sigmoid(gap/τ); when gap=0, sigmoid(0/τ)=sigmoid(0)=0.5 regardless of τ, since scaling zero by any temperature still yields zero.
Why does hard-negative mining specifically raise false-negative risk?
Mining deliberately searches for candidates similar to the positive -- the exact same similarity region a genuinely relevant, unlabeled document would also occupy.

CAREER PRACTICE

Interview questions

Conceptual: why do hard negatives teach more than easy ones?
A hard negative keeps the gap between positive and negative small, so the loss stays meaningful and gradient signal survives; an easy negative's gap is already large, so the loss collapses toward zero and there's little left to learn from it.
Mathematical: state and verify the softplus/sigmoid form.
Loss = softplus(−gap/τ) = −log(sigmoid(gap/τ)), algebraically identical to Concept 04's numerator/denominator cross-entropy form -- verified to match on every row of Section 10's table.
Coding: implement the 2×2×τ matrix.
Section 12 gives the full implementation, reusing Concept 04's infonce_loss() unchanged over the four (positive, negative) pairs at both temperatures.
Debugging: a fine-tuned retriever plateaus early. What should you check about its negatives?
Whether negatives are staying easy (already well-separated) as training progresses -- if so, the loss has little left to teach, and mining harder negatives (or increasing batch size for more in-batch candidates) is the fix, not more training steps on the same easy negatives.
System design: sketch a hard-negative mining pipeline for a support-ticket RAG corpus.
Index the corpus (Module 05's BM25 or an ANN index), retrieve top candidates for each labeled positive, exclude the true positive and any candidate close enough to require a relevance re-check, and feed the remainder in as hard negatives -- the actual algorithm is Module 24's job, forward-referenced here only.
