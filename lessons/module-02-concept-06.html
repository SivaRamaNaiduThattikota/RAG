01 · CONCEPT FIRST

What pretraining actually nudges, now that you can name the parts

Module 01, Concept 05 already told you training changes parameters, inference does not. This concept does not repeat that test — it answers the question that test left open: which parameters, specifically, and computed from what? During pretraining, a gradient reaches the token embedding table, every block's attention and feed-forward weights (Concepts 03–04), and the output head (Concept 05) — all at once, every training step. What it is minimizing is the exact cross-entropy loss on the probability distribution Concept 05's softmax already produces for the true next token.

Fine-tuning reaches the same weight groups, on different, curated data. Alignment changes what the loss compares against — previewed here only, since full RLHF mechanics are out of scope for RAG Atlas.

First memory: pretraining, fine-tuning and alignment all touch the same weight groups you already met; they differ in the data and the objective, not in which matrices exist.
02 · WHY IT EXISTS

"Training updates parameters" was abstract until you had parameters to name

Before Concepts 03–05, "training updates the model's weights" had no shape — you had not yet seen an attention weight, a feed-forward weight, or the output head's matrix. Now that you have, the same sentence can be made concrete: a training step computes a loss from the output head's own logits, and backpropagation carries a correction signal from that one loss value into every weight matrix the forward pass touched on the way there.

WHAT CONCEPT 05 GAVE YOU

The forward-only path: hidden vector → output head → logits → softmax → distribution.

WHAT THIS CONCEPT ADDS

A loss computed on that distribution, and a backward path carrying gradients into the output head, every block, and the embedding table.

03 · CONCRETE EXAMPLE

One training step on "The leave policy allows…unlimited"

Take a pretraining document containing the sentence "The leave policy allows unlimited carryover." At the position after "…allows," the true next token is unlimited. The forward pass runs exactly as Concept 05 traced it: final hidden vector → output head → logits → softmax. Say softmax assigns unlimited a probability of 20% at this early, undertrained step. The loss for this one position is -ln(0.20) ≈ 1.61. Backpropagation then pushes every weight the forward pass used — that position's attention and feed-forward weights, the output head's row for unlimited, and the embedding rows for every input token — slightly toward assigning unlimited a higher probability next time.

FORWARD PASS

Identical mechanism to Concept 05 — nothing new here.

LOSS

Cross-entropy on the true next token's softmax probability — new this concept.

BACKWARD PASS

Gradients reach the embedding table, every block, and the output head — new this concept.

04 · TECHNICAL MECHANISM

What each stage concretely touches

PRETRAINING

Embedding table + blocks + output head

All three, every step, minimizing next-token cross-entropy from the output head's softmax on raw text.

SUPERVISED FINE-TUNING

Same weight groups, curated data

The identical cross-entropy loss on the identical output head, computed only over curated instruction-response pairs rather than raw text.

PREFERENCE / ALIGNMENT (PREVIEW)

Same weights, a different comparison

Instead of one true-token cross-entropy, the signal ranks or scores whole responses against each other. Full RLHF mechanics are out of scope for RAG Atlas — this is a boundary, not a derivation.

LoRA / PEFT (FROM MODULE 01)

Small matrices around a frozen stack

Concept 05's block weights and output head stay frozen; only small adapter matrices, added alongside them, receive gradients.

WHAT NEVER GETS A GRADIENT

Fixed structural choices

The number of blocks, the number of attention heads, and RoPE's fixed rotation angles (Concept 04) are architecture choices, not learned weights — no training stage touches them.

INFERENCE

Forward pass only

Every weight above is read, none is written — Concept 05's path, unchanged.

07 · COMMON MISTAKES

What beginners often misunderstand

"Only the output head updates during pretraining."

The embedding table and every block's attention and feed-forward weights update too — the output head is just where the loss is computed.

"Fine-tuning uses a different loss function than pretraining."

Supervised fine-tuning almost always reuses the identical next-token cross-entropy; what changes is the data and, usually, which tokens count toward the loss.

"Alignment is just fine-tuning with a stricter prompt set."

Alignment methods compare or rank whole responses instead of scoring one true next token — a genuinely different signal, previewed but not derived here.

"RoPE's rotation angles get updated like the embedding table."

RoPE (Concept 04) is a fixed geometric rule, not a learned weight — no training stage changes it.

"Backpropagation is a separate mechanism from the forward pass."

It reuses the exact same weights and the exact same computation graph the forward pass just built, run in reverse.

"A frozen base model for LoRA means nothing in the stack changes."

The stack's own weights stay frozen; small adapter matrices added alongside them are exactly what receives the gradient.

04
INTUITION

Grading the scorecard, then correcting the whole chain that filled it in

Concept 05 compared the output head to a scorecard filled out in one pass. This concept adds a grader: it checks the score given to the one word that was actually correct, turns a low score into a "how wrong was this" number, and sends a correction backward through every step that helped produce that score — the blocks that built the hidden vector, and the embedding rows that started it.

Analogy boundaryNothing here is a search over correction strategies. Backpropagation follows one fixed rule — the chain rule of calculus — through the exact same computation graph the forward pass already built; it does not "decide" how to fix the weights, it computes an exact derivative.

06
MECHANISM

Two paths through the same weights: forward-only and forward-plus-backward

INFERENCE — FORWARD ONLY
Embedding lookup for the prompt tokens
Blocks compute attention and feed-forward outputs
Output head produces logits, softmax produces a distribution
Decoding picks a token (Concept 07) — no loss, no gradient, no update
PRETRAINING / SFT — FORWARD + LOSS + BACKWARD
Identical forward pass through embedding, blocks, output head
Cross-entropy loss compares softmax's true-token probability to 1
Backward pass computes ∂L/∂weight for every weight the forward pass used
Optimizer nudges the embedding table, block weights, and output head

Both lanes run the exact same forward computation. The only structural difference this concept adds is whether a loss and a backward pass follow it.

09
MATHEMATICS

Cross-entropy on Concept 05's own softmax, and its gradient

L = −log(p_true), where p = softmax(z) and z = h · W_outt + b

z is exactly Concept 05's logit vector; p_true is the softmax probability the model assigned to the token that actually came next. A confident, correct prediction (p_true near 1) gives a loss near 0; an confident wrong prediction gives a large loss.

∂L/∂z_i = p_i − 1{i = true}

This is the well-known softmax-plus-cross-entropy gradient: for the true token's logit it equals p_true − 1 (negative, pushing that logit up); for every other token it equals p_i (positive, pushing that logit down). This vector is exactly what flows backward into the output head's rows, and — via the chain rule, through every block — into the attention and feed-forward weights and the embedding table.

θ ← θ − η · ∂L/∂θ, for θ ∈ {embedding table, block weights, output head}

This is Module 01 Concept 05's gradient-descent update rule, unchanged; the only addition here is naming θ as the three specific weight groups this concept traced, instead of leaving it abstract.

10
WORKED EXAMPLE

Cross-entropy and its gradient on a toy three-token vocabulary

Toy logits for the position after "…allows," over three candidate tokens: z = [1.2, 0.9, 0.3] for [unlimited, several, many], with true token unlimited.

softmax: e^1.2≈3.32, e^0.9≈2.46, e^0.3≈1.35; sum≈7.13 → p ≈ [0.466, 0.345, 0.189]
loss: L = −log(0.466) ≈ 0.764
gradient ∂L/∂z: [0.466−1, 0.345, 0.189] = [−0.534, 0.345, 0.189]

The negative entry on unlimited means training will push that logit up; the positive entries on several and many mean training will push those down — all from one loss value, computed on the same three logits Concept 05's mechanism already knows how to produce.

12
CODE

One training step, from scratch, on the output head

PYTHON · NUMPY-STYLE PSEUDOCODE 
import numpy as np

def softmax(z):
    z = z - np.max(z)
    e = np.exp(z)
    return e / np.sum(e)

def cross_entropy_loss(z, true_index):
    p = softmax(z)
    return -np.log(p[true_index]), p

def loss_gradient_wrt_logits(p, true_index):
    grad = p.copy()
    grad[true_index] -= 1          # softmax + cross-entropy gradient
    return grad                    # this is what flows backward into W_out, then the blocks, then embeddings

# one toy step, reusing Concept 05's forward mechanism
h = np.array([1.0, 1.0])                       # final hidden vector
W_out = np.array([[0.95, 0.95],                 # 'unlimited'
                   [0.75, 0.75],                 # 'several'
                   [0.30, 0.30]])                # 'many'
true_index = 0                                  # 'unlimited' actually came next

z = W_out @ h                                    # Concept 05's projection
loss, p = cross_entropy_loss(z, true_index)      # new this concept
grad_z = loss_gradient_wrt_logits(p, true_index) # new this concept

# grad_z now backpropagates into W_out's rows, then — through the chain rule —
# into every block's attention/feed-forward weights and the embedding table.
13
ECOSYSTEM

What production training code actually calls this

In Hugging Face transformers, a causal language model's forward call returns a loss field computed with exactly this shifted-cross-entropy pattern whenever labels are passed in; Trainer and SFTTrainer (from the trl library) wrap that same loss with data loading, optimizer scheduling, and checkpointing. Preference-alignment libraries such as trl's DPO or PPO trainers replace this single-token cross-entropy with a pairwise or reward-based objective over whole responses — the same three weight groups traced above still receive the gradient, but the previewed alignment signal computing it is intentionally not derived in this course.

16
DIAGNOSIS

Failure modes

LOSS MASKING BUG

Prompt tokens counted in the loss

Failing to mask prompt/instruction tokens during SFT trains the model to also predict its own inputs.

CATASTROPHIC FORGETTING

All three groups move together

Because fine-tuning touches the same weight groups as pretraining, aggressive updates can overwrite general capability while specializing.

VANISHING/EXPLODING GRADIENTS

Backward pass through many blocks

The chain rule through a deep block stack can shrink or blow up gradients reaching the embedding table.

REWARD HACKING (PREVIEW)

Alignment optimizes the wrong signal

A model can learn to satisfy a flawed preference or reward signal rather than genuine quality — a known risk of the alignment stage this concept only previews.

MISMATCHED TOKENIZATION

Fine-tuning data tokenized differently

If fine-tuning data is tokenized inconsistently with pretraining, the embedding rows being updated may not align with what pretraining already learned.

FROZEN-BASE ASSUMPTION

Expecting LoRA to change everything

Behavior LoRA cannot reach because the frozen base never represented it well in the first place.

18
REALITY

Production implications

  • Full fine-tuning requires storing gradients and optimizer state for every parameter in all three weight groups, multiplying memory cost well beyond the checkpoint size alone.
  • LoRA and other PEFT methods reduce that trainable memory footprint by orders of magnitude, at the cost of representational capacity confined to the frozen base.
  • Loss masking correctness in SFT pipelines is a common, quiet source of degraded instruction-following — verify which tokens contribute to the loss.
  • Alignment pipelines (previewed only) typically add a separate reward or preference model and its own training and evaluation infrastructure, on top of everything this concept traced.
  • None of this runs inside your RAG service at request time — the generator and embedding models you call were already through every stage above, and your system only performs inference.
  • Track exactly which stage, dataset version, and base checkpoint produced any model you deploy — this concept's weight groups are meaningless without that lineage.

21
FEEDBACK

Solution and teach-back

Open one worked reasoning pattern
With four toy logits, softmax turns them into probabilities that sum to one; the cross-entropy loss is just the negative log of whatever probability landed on the true index. The gradient vector subtracts 1 from that one true-token entry and leaves the others as their raw probabilities — small if the model was already confident and correct, large if it was confidently wrong. From there, that gradient vector is exactly what the chain rule carries backward through the output head's matrix, through every block's attention and feed-forward weights, and into the embedding rows for the tokens that were actually fed in. Inference never produces this vector at all, because inference never computes a loss in the first place — there is no true label to compare against and nothing to send backward.

23
CAREER PRACTICE

Interview questions

Walk through exactly what happens, mechanically, during one pretraining step.
A forward pass produces logits from the output head and a softmax distribution over them, exactly as in Concept 05; cross-entropy compares the true next token's probability to 1; the resulting gradient vector backpropagates through the output head, every block's attention and feed-forward weights, and the embedding table, and an optimizer applies a small update to each.
Does supervised fine-tuning require a new loss function?
Almost always no — it reuses the identical cross-entropy loss on the identical output head; what changes is the training data (curated instruction-response pairs) and often which tokens are masked out of the loss.
What does LoRA freeze, and what receives the gradient instead?
It freezes the embedding table, block weights, and output head entirely; small low-rank adapter matrices added alongside the frozen weights receive the gradient instead.
A colleague claims alignment and pretraining optimize the same loss. How do you respond?
Pretraining and SFT both score one true next token with cross-entropy; alignment methods instead compare or rank whole candidate responses against each other — a different signal touching the same weight groups, whose full mechanics this course previews but does not derive.
