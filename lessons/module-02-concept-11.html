Structured generation,
and constrained outputs

Concept 10 showed that evidence sitting inside the context window isn't always attended to reliably. This concept turns to a different axis entirely: even a fluent, well-attended answer isn't automatically a machine-parseable one. A JSON parser, a tool-call executor, or a citation validator needs a hard shape guarantee on every single call — not a habit the model usually keeps. That guarantee has to be enforced at the token level, as a mask on Concept 07's decode loop, not requested in words inside the prompt. PROGRESSIVE BEGINNER CORE

A mask, not a request — the same scores, a guaranteed shape

Concept 07 built the decode loop: logits in, a token out, every step, until a stop condition fires. This concept adds exactly one new step to that loop — a mask that narrows the candidate tokens down to whichever ones keep the output legal, before the decode rule ever runs. Nothing about Concept 07's greedy, temperature, or top-k logic changes. What changes is what it's allowed to choose from.

01 · CONCEPT FIRST

A mask on Concept 07's distribution, not a polite request in the prompt

Constrained decoding — also called grammar-guided decoding — is a mask applied to the per-step token distribution Concept 07's decode loop already produces at every position. At each step, the mask forces the output to keep a fixed shape: valid JSON, a specific schema, or one of a small fixed set of choices. Any token that would break that shape gets its probability zeroed out before the decode rule ever gets to pick from the distribution.

That is a completely different thing from asking the model nicely, in the prompt, to "respond only in JSON" or "pick exactly one of these three options." A prompt instruction changes what the model is likely to produce. A mask changes what it is possible for the model to produce at that step. One is a habit; the other is a guarantee.

First memory: constrained decoding is a mask inserted between Concept 04's logits and Concept 07's decode rule — it narrows the candidates, it never asks for good behavior. "Please respond in JSON" is a request. A grammar mask is a constraint the invalid tokens cannot survive.
02 · WHY IT EXISTS

"Usually right" is not the bar a parser needs cleared

Fluent, high-probability text is exactly what Concept 07's decode loop is built to produce, and for most conversational output that's the entire goal. But the moment that output has to feed a downstream system — a JSON parser, a tool-call executor, a citation validator, a routing field that only accepts three legal values — "usually correct" stops being good enough. A parser either successfully parses the string or it throws on that exact call. There's no partial credit at the boundary between "the model behaved well 99 times out of 100" and the one call that breaks production.

PROMPTED FORMATTING'S JOB

Raise the odds the model happens to produce the right shape on its own, by describing that shape in words. No enforcement — just a strong hint.

ENFORCED MASKING'S JOB

Make the wrong shape structurally impossible to generate at each step, regardless of how the model would have behaved unconstrained.

03 · CONCRETE EXAMPLE

A three-value routing field, and the invalid word that almost won

Oracle RAG needs a routing decision field that must be exactly one of three values: approved, denied, or pending. At the decode step that produces this field, the model's raw, unconstrained distribution actually ranks a fourth word — unclear — as its single highest-probability token. It's a fluent, reasonable-sounding word. It is also not a legal value for this field.

UNCONSTRAINED DECODE STEP

Same raw scores, no mask applied: the top pick is unclear — fluent, but not one of the three values this field is allowed to hold.

GRAMMAR-MASKED DECODE STEP

Identical raw scores, mask applied first: unclear is zeroed out before the decode rule ever sees it, so the top pick becomes approved — a legal value, guaranteed.

04 · TECHNICAL MECHANISM

Six moving parts, one narrow job each

AUTOMATON STATE

How much of the shape exists so far

A grammar/schema automaton tracks how much of the target output has already been produced at this exact step.

ELIGIBLE TOKEN SET

What could legally come next

From that state, the automaton computes exactly which tokens would keep the output inside the required shape.

LOGIT MASKING

Zero out everything else

Every token outside the eligible set has its probability driven to zero before any decoding decision happens.

RENORMALIZE

One unit of weight, redistributed

The surviving tokens' scores are renormalized so they still sum to one — Concept 04's softmax guarantee, run over a smaller set.

HANDOFF TO CONCEPT 07

The decode rule runs unmodified

Greedy, temperature, top-k — whichever rule Concept 07 already defined runs exactly as before, just on the narrowed distribution.

NOT A CONTENT CHECK

Shape only, never truth

The mask never asks whether a token is factually correct — only whether it's legal at this position in the grammar.

07 · COMMON MISTAKES

What beginners often misunderstand

"JSON mode guarantees my exact fields and types."

Plain JSON mode typically guarantees syntactically valid JSON only — not that your specific keys, types, or enum values show up, unless schema-aware guided decoding is layered on top.

"Constrained decoding fixes hallucinated facts."

It constrains form, not content. A grammar-valid answer can still be confidently, fluently wrong — Concept 09's boundary doesn't move.

"This requires retraining or fine-tuning the model."

It's a decode-time technique. Zero training happens; the mask is computed fresh at inference, on top of whatever model you already have.

"It replaces greedy or temperature decoding."

It doesn't replace Concept 07's decode rule at all — it narrows what that rule gets to choose from, then hands off unchanged.

CITATION FORMATForce a fixed tag, e.g. [Doc3]

The Text-to-SQL branch needs a tool call whose argument JSON always parses and always matches the expected argument schema — a generation-shape control, not a retrieval improvement.

09 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

Mask-then-decode ordering

The grammar mask runs first, narrowing the candidates; Concept 07's decode rule runs second, unchanged, on what's left.

Shape vs. factual correctness

The mask guarantees the output is well-formed. It says nothing about whether the content inside that shape is true.

No training required

This is a decode-time technique — applied at inference, with zero changes to the model's weights.

Bigger models still need it

A larger or better model may need the mask less often, but "usually right" is never the same guarantee as "structurally cannot be wrong."

04
INTUITION

A form whose pen physically cannot ink the wrong thing

Picture a fill-in-the-blank form with a locked template: a numeral box whose pen only inks digits, a checkbox whose pen only inks checked or unchecked. You can't write "maybe" in the numeral box — not because you were told not to, but because the pen simply won't make that mark there. That's constrained decoding. Compare it to writing freely on a blank page, where nothing physically stops you from writing anything at all, no matter what the instructions at the top of the page ask for.

Analogy boundaryUnlike a paper form, this mask isn't set once at print time — it's recomputed fresh at every single token position, from a live automaton that's tracking exactly how much of the shape exists so far. And it never once inspects whether what's being written is true. It only ever asks whether the mark is legal at that blank — form validity and content correctness are handled by two completely different checks.

06
MECHANISM

One lane untouched, one lane new and running first

LANE A — CONCEPT 07'S DECODE STEP, UNCHANGED
Logits arrive
Temperature / greedy / top-k chooses among whatever candidates it's given
Nothing about this lane's logic is modified by this concept
LANE B — THE NEW MASKING STEP, RUNS FIRST
Automaton state read for this position
Eligible set E_t computed from that state
Non-eligible logits set to −∞, distribution renormalized

Lane B always runs before Lane A, and Lane B never replaces Lane A — it only shrinks what Lane A is allowed to pick from. If Lane B narrows the field to exactly one token, Lane A's choice is trivial. If Lane B leaves ten tokens standing, Lane A's greedy/temperature/top-k logic still decides among them exactly as Concept 07 defined.

09
MATHEMATICS

Formalizing the mask, then handing off to Concept 07's softmax

The mask itself is a simple substitution over the raw logits, keyed by the eligible set E_t the automaton computes for the current step:

z'_i = z_i, for i ∈ E_t; z'_i = −∞, for i ∉ E_t

Plug the masked logits z' straight into Concept 07's already-taught softmax-with-temperature equation — cited, not rederived — restricted to the surviving indices:

P(token_i) = exp(z'_i / T) / Σ_{j∈E_t} exp(z_j / T)

Contrast this against Concept 07's top-k: top-k's candidate subset is chosen by probability rank — the k highest-scoring tokens, whatever they happen to be. This concept's E_t is chosen by grammar legality — whichever tokens the automaton says are allowed, regardless of their score. The two subsets need not overlap at all. E_t can shrink to exactly one token, in which case the "decoding decision" is really just the mask deciding for you — or, in a buggy or over-strict grammar, E_t can shrink to size zero, an automaton deadlock covered in Section 16.

10
WORKED EXAMPLE

The routing field, with real numbers

Back to Section 03's enum field. Raw logits over four candidate tokens at this decode step: approved = 2.1, denied = 1.8, pending = 1.2, unclear = 2.6. Run Concept 07's ordinary softmax over all four, unconstrained:

exp(2.1)=8.17, exp(1.8)=6.05, exp(1.2)=3.32, exp(2.6)=13.46 — sum ≈ 31.00
unconstrained weights → approved 26.3%, denied 19.5%, pending 10.7%, unclear 43.4% — "unclear" wins

Now apply this concept's mask. The grammar only allows the three enum values, so E_t = {approved, denied, pending} and unclear's logit goes to −∞ before renormalizing over the survivors:

exp(2.1)=8.17, exp(1.8)=6.05, exp(1.2)=3.32 — sum ≈ 17.54
masked weights → approved 46.6%, denied 34.5%, pending 18.9% — "approved" wins

Same three real scores throughout. Masking alone flips the argmax from an invalid token to a valid one — nothing about the model's underlying judgment changed, only what it was allowed to say out loud.

CODE

Wrapping Concept 07's decode step, not replacing it

PYTHON · FROM-SCRATCH PSEUDOCODE 
def eligible_tokens(tokens_so_far, grammar):
    # toy grammar checker -- returns the set of token ids that keep
    # tokens_so_far inside the target shape one step further
    return grammar.next_allowed(tokens_so_far)

def masked_decode_step(logits, tokens_so_far, grammar, temperature):
    allowed = eligible_tokens(tokens_so_far, grammar)     # E_t for this step
    masked_logits = [
        value if token_id in allowed else float("-inf")
        for token_id, value in enumerate(logits)
    ]
    # decode_step is Concept 07's existing function -- completely untouched.
    # only its input changed: a narrower, renormalized distribution.
    return decode_step(masked_logits, temperature)

# usage inside Concept 07's unmodified generation loop:
# next_token = masked_decode_step(logits, tokens_so_far, grammar, temperature=0.7)

ECOSYSTEM

Where this actually lives in production today

llama.cpp's GBNF grammars compile a BNF grammar into per-state token masks computed at inference time — a concrete, widely-deployed implementation of exactly Section 06's Lane B. Outlines-style guided generation (Willard & Louf) takes a different route to the same eligible set: it compiles a regex, CFG, or JSON Schema into a finite-state automaton up front, so the eligible set is looked up per step instead of recomputed by brute force — the practical answer to Section 16's latency failure mode. Provider-level structured-output and function-calling APIs expose this whole layer as a schema argument on the call, hiding the automaton entirely behind the API surface. LangChain's later structured-output wrappers, further into this course, call into exactly this decoding layer rather than implementing a competing algorithm of their own.

16
DIAGNOSIS

Failure modes

DEGENERATE FILLER

Valid but empty of content

An over-strict schema can force repetitive, degenerate filler that passes every validity check while saying nothing useful.

AUTOMATON DEADLOCK

An empty eligible set, no defined fallback

A buggy grammar can produce E_t = ∅ at some step, with no legal token to pick — a grammar bug, not a model failure, and generation has nothing sane to do next unless a fallback exists.

UNCOMPILED-GRAMMAR LATENCY

Recomputing the eligible set from scratch

Computing E_t by brute force over a large vocabulary at every step, instead of via a precompiled automaton, adds real per-token cost.

VALID MISTAKEN FOR TRUE

Concept 09's boundary again

"Passed JSON-schema validation" and "factually correct" are two separate properties — passing one never implies the other.

GRAMMAR/SCHEMA VERSION DRIFT

The decoder and the parser disagree

The grammar the decoder enforces and the schema the downstream parser expects can quietly fall out of sync across a deploy.

18
REALITY

Production implications

  • Version and test grammars/schemas alongside prompts, as first-class deploy artifacts — not an afterthought bolted onto a prompt template.
  • Define an explicit fallback for automaton deadlocks — an early, schema-valid close, for instance — instead of letting generation hang with no legal move.
  • Log both the raw and the masked decision at spot-checked steps, so debugging a bad output doesn't require guessing which lane caused it.
  • Keep schema-validity checks and faithfulness/factuality evaluation as two separate metrics, never a single pass/fail number.
  • Account for grammar-compilation cost separately from per-token decoding cost when sizing latency — an uncompiled grammar can dominate the wrong part of the budget.
19
RECALL

Knowledge check

Why does the mask run before, not instead of, Concept 07's decode rule?
The mask only narrows the candidate set the decode rule is allowed to choose from. If it replaced the decode rule, there'd be nothing left to decide among multiple surviving legal tokens — Lane A still does that job, just on a smaller input.
Why isn't a valid-JSON guarantee the same as a schema guarantee?
Valid JSON only means the string parses. A schema guarantee additionally requires the right keys, types, and enum values — a strictly stronger, independently-failable property.
Why doesn't constrained decoding reduce hallucination of facts?
The mask only ever evaluates grammar legality at each step, never truth. A hallucinated fact that happens to fit the required shape passes the mask without being detected at all.
What is an automaton deadlock, and why is it a grammar bug rather than a model failure?
It's a step where the eligible set E_t is empty — no token keeps the output legal. The model didn't fail to produce a good token; the grammar failed to leave any token available at all, which is a defect in the grammar's design.

FEEDBACK

Solution and teach-back

Open the worked solution
At this position — right after [Doc, before a closing bracket is legal — the grammar demands exactly one digit next. That masks out both "]" and "the", leaving E_t = {"1", "2", "3"}. Unconstrained, the full five-way softmax gives "]" the highest share at roughly 39.0% — the model's overall top pick, and an invalid one, since it would close the tag before any digit appears. Masked to just the three digits, exp(1.4)=4.06, exp(1.1)=3.00, exp(0.9)=2.46, summing to about 9.52; the renormalized weights come out to roughly "1" 42.6%, "2" 31.6%, "3" 25.8% — "1" wins. The unconstrained and masked winners differ: "]" unconstrained, "1" masked — the identical pattern Section 10 already showed with the enum field, now applied to a citation tag. PORTABLE MEMORY

Concept card

The mechanism

Constrained decoding is a mask over Concept 07's per-step distribution, sitting inside the LLM box between the logits and the decode rule. Its core equation is a masked softmax restricted to the eligible set E_t — the identical raw scores, renormalized over fewer survivors. Use cases include tool-call arguments, citation tags, and enum routing. Warning signs are automaton deadlock and mistaking a valid shape for true content.

Selection rule

  • Grammar mask runs first; Concept 07's decode rule runs second, unmodified
  • Shape validity and factual correctness are two separate, independently-failable checks
  • No training required — this is purely a decode-time technique
  • Memorable example: masking flips the argmax from invalid "unclear" to valid "approved" using the exact same raw scores

CAREER PRACTICE

Interview questions

A teammate only knows "JSON mode." How do you explain grammar-constrained decoding to them?
JSON mode guarantees the string parses as JSON. Grammar-constrained decoding goes further: it compiles a schema or grammar into per-step eligible token sets, so the output can be guaranteed to match your exact fields, types, and enum values too — not just be parseable at all.
Why can't a bigger model alone replace this guarantee?
A bigger model can raise the odds of the right shape, but "usually right" is a tendency, not a guarantee — a machine-critical parser needs the shape to be structurally impossible to violate, which only a per-step mask provides regardless of model size.
How would you debug a grammar that occasionally deadlocks in production?
Log the automaton state and the eligible set at every step for the failing calls, find the state where E_t comes back empty, and trace that back to the grammar rule that failed to leave any legal continuation — then add either a grammar fix or an explicit fallback transition for that state.
Compare the cost, latency, and guarantee trade-offs of constrained decoding versus generate-then-validate-and-retry.
Constrained decoding adds per-step masking overhead and needs a compiled grammar, but guarantees valid shape on every call with no wasted generations. Generate-then-validate-and-retry is simpler to bolt on but can waste calls, loop, or exhaust retries, and only guarantees validity eventually, not on the first attempt.
