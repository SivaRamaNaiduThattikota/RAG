01 · CONCEPT FIRST

Tokens, token IDs, and modalities

Tokenization splits raw input into a sequence of smaller pieces called tokens. Each token is looked up in a fixed vocabulary and replaced with an integer token ID. A token can be a whole word, part of a word, a single character, or a punctuation mark—never assume it is a whole word.

Modality describes the kind of input: text, image, audio, or video. Non-text modalities are also converted into discrete or near-discrete units—image patches, audio frames—before a model can process them the same way it processes text tokens.

First memory: a token is a vocabulary entry, not a word.
02 · WHY IT EXISTS

Why not feed the model raw characters or whole words?

A model needs a fixed, finite set of input symbols. Character-level vocabularies keep the set small but produce very long sequences and weak per-symbol meaning. Whole-word vocabularies produce short sequences but grow enormous and still fail on new or rare words. Subword tokenization is the practical middle point: a modest vocabulary that can represent almost any input by combining known pieces.

TOO FEW SYMBOLS

Character-level: tiny vocabulary, very long sequences, little meaning per step.

TOO MANY SYMBOLS

Whole-word: short sequences, huge vocabulary, breaks on unseen words.

03 · CONCRETE EXAMPLE

“Oracle23ai retrieves the leave policy.”

A common word like the is almost always one token. A domain-specific term like Oracle23ai is rare in general training data, so a subword tokenizer usually breaks it into several pieces, for example Oracle, 23, and ai. The sentence is not six words and six tokens—it can easily become nine or ten tokens once rare terms fragment.

COMMON WORD

the → one token, already in the vocabulary.

RARE / DOMAIN TERM

Oracle23ai → multiple tokens, assembled from known pieces.

PUNCTUATION

. → its own token, separate from the preceding word.

04 · TECHNICAL MECHANISM

How tokenizers split input

CHARACTER-LEVEL

Every character is a token

Smallest possible vocabulary; sequences become very long.

WORD-LEVEL

Split on whitespace

Short sequences; huge vocabulary; unseen words fail outright.

BYTE-PAIR ENCODING

Merge frequent pairs

Learns a subword vocabulary by repeatedly merging the most frequent adjacent pair.

WORDPIECE / SENTENCEPIECE

Related subword schemes

Different merge or likelihood criteria; SentencePiece also works directly on raw Unicode or bytes for language independence.

SPECIAL TOKENS

Reserved vocabulary entries

Beginning/end-of-sequence, padding, and role markers such as system, user, and assistant.

NON-TEXT MODALITIES

Patches and frames

Images are split into fixed-size patches; audio is split into short time frames—then embedded like tokens.

05 · ARCHITECTURE / FLOW

Two tokenizers, two vocabularies

EMBEDDING-MODEL TOKENIZER

Chunks are tokenized with the embedding model’s own vocabulary before being converted into vectors for the index.

GENERATOR-MODEL TOKENIZER

The prompt, retrieved context, and question are tokenized with the LLM’s own vocabulary before generation.

Text / image / audio → Tokenizer → Token IDs → Embedding lookup → Model input

06 · IMPORTANT DISTINCTIONS

Terms that get collapsed into “token”

Term What it actually is Common confusion
Character One letter, digit, or symbol Assumed identical to a token
Word A whitespace-separated unit in most written English Assumed to equal exactly one token
Token A vocabulary entry produced by a specific tokenizer Treated as universal across models
Token ID The integer index of a token inside one vocabulary Confused with the embedding itself
Embedding The dense vector a token ID is mapped to Confused with the token ID that produced it

A tokenizer and its vocabulary belong to one model or model family. Token IDs from one tokenizer are meaningless to a model trained with a different vocabulary.

07 · COMMON MISTAKES

What beginners often misunderstand

“One word equals one token.”

Rare, long, or domain-specific words routinely split into several subword tokens.

“Token count is close enough to character count.”

The ratio varies by language, script, and content—code and non-English text often use more tokens per character.

“Token IDs from one model work with another.”

Token IDs are only meaningful with the exact vocabulary that produced them.

“Images and audio are not tokenized.”

Vision and audio models discretize patches or frames into token-like units before a transformer processes them.

“A longer prompt always adds more information.”

Padding and special tokens consume the token budget without adding content.

“Tokenizers never change.”

Vocabulary and tokenization can change between model versions and providers.

08 · YOUR PROJECT MAPPING

Where tokens matter in Oracle RAG

CHUNK SIZING Measure chunks in tokens, not characters

Embedding models and the LLM both enforce token limits, not character limits.

CONTEXT BUDGET Reserve tokens for prompt, evidence, and answer

Instructions, retrieved passages, citations, and the question all share one finite context window.

MULTIMODAL DOCUMENTS Plan tokenization before ingestion, not after

Scanned PDFs, tables, and images must become tokenizable text—or a dedicated multimodal representation—before retrieval.

COST AND LATENCY Track token usage per request

Provider billing and response time both scale with sequence length, in tokens.

LangChain and LangGraph expose token-aware text splitters and length functions, but the tokenizer and vocabulary they call still belong to the specific embedding or generation model, not to the framework.

04
INTUITION

A small kit of standard pieces

Think of a tokenizer as a fixed kit of standard pieces—like a limited set of printing-press type. Any input, however unusual, must be assembled from that same finite kit. Common words already exist as single pieces; unusual words are built by combining several smaller pieces.

Analogy boundaryThe pieces are chosen by frequency in training data, not by human ideas of syllables or meaning—so a subword split rarely lines up with how a person would break the word down.

06
MECHANISM

How byte-pair encoding builds a vocabulary

Start from individual characters or bytes
Count frequency of every adjacent symbol pair in training text
Merge the single most frequent pair into a new symbol
Repeat counting and merging for a fixed number of steps
Save the final set of symbols as the vocabulary
At use time, apply the same merges to new text, longest match first

The vocabulary is learned once, offline, from a large text corpus. Tokenizing new text at inference time only applies the already-learned merges—it does not learn anything new.

08
ARCHITECTURE

Tokenization happens twice in RAG

Documents ↓ Chunks ↓ Embedding-model tokenizer ↓ Embedding vectors ↓ Vector index

The generator sees an entirely separate tokenization pass: the assembled prompt, retrieved chunks, and question are tokenized by the LLM’s own tokenizer immediately before generation, using a vocabulary that has no required relationship to the embedding model’s vocabulary.

09
MATHEMATICS

Vocabulary size and sequence length

Embedding lookup: e_t = E[t], where E ∈ R^(|V| × d) and t is a token ID

|V| is the vocabulary size and d is the embedding dimension. Every token ID t selects one row of the lookup matrix E—this is the first step inside the model, immediately after tokenization.

Trade-off: larger |V| → shorter sequences, larger lookup table; smaller |V| → longer sequences, smaller table

Byte-pair encoding is a practical compromise on this trade-off: a vocabulary in the tens of thousands keeps both the lookup table and typical sequence lengths manageable.

10
WORKED EXAMPLE

Counting tokens by hand

Take the sentence Oracle23ai retrieves the leave policy. — 6 whitespace-separated words, 39 characters including the space count.

Illustrative subword split: [Oracle][23][ai] [retriev][es] [the] [leave] [policy] [.]

That split produces 9 tokens from 6 words—a ratio of 1.5 tokens per word driven entirely by one rare term and one common suffix. The same sentence would need 39 tokens under a character-level tokenizer, and could fail outright under a strict whole-word tokenizer if Oracle23ai is not in its fixed vocabulary.

CODE

A minimal whitespace tokenizer

PYTHON · FROM-SCRATCH PSEUDOCODE 
# A minimal tokenizer: whitespace + punctuation splitting only.
# Real subword tokenizers additionally split rare words into
# learned pieces; this version keeps the mechanism visible.

vocab = {"the": 0, "leave": 1, "policy": 2, "retrieves": 3, ".": 4}
UNK = len(vocab)

def encode(text):
    words = split_words_and_punctuation(text)
    return [vocab.get(word, UNK) for word in words]

def decode(ids, vocab):
    id_to_token = {v: k for k, v in vocab.items()}
    return " ".join(id_to_token.get(i, "") for i in ids)

tokens = encode("the leave policy.")
# tokens == [0, 1, 2, 4]

ECOSYSTEM

Production tokenizer libraries

Hugging Face tokenizers and tiktoken-style libraries ship trained BPE, WordPiece, or SentencePiece vocabularies matched to a specific model release, handle Unicode normalization and byte-level fallback for unknown symbols, and run fast enough for production request volume. LangChain’s token-aware text splitters call into these same libraries to estimate chunk length in tokens rather than characters—the splitter does not invent its own tokenizer.

Granularity Vocabulary size Sequence length Unseen-word handling
Character-level Very small Very long Always representable
Word-level Very large Short Fails on out-of-vocabulary words

16
DIAGNOSIS

Failure modes

BUDGET

Silent truncation

A chunk sized in characters unexpectedly exceeds the model’s token limit and gets cut off.

COST

Unexpected token inflation

Code, tables, or certain languages consume far more tokens per character than assumed.

MISMATCH

Wrong tokenizer, wrong model

Token IDs computed with one vocabulary are meaningless to a model trained on another.

FORMATTING

Missing special tokens

Omitting role or boundary tokens can break chat-formatted prompts.

UNICODE

Byte-fallback edge cases

Emoji, rare scripts, or malformed encodings can tokenize unexpectedly.

CHUNKING

Character-based chunk boundaries

Chunking by characters produces inconsistent token counts across chunks.

18
REALITY

Production implications

  • Budget chunk size, prompt template, retrieved evidence, and answer length in tokens, not characters.
  • Track token usage per request; most providers bill and rate-limit by token count.
  • Pin the tokenizer version to the model version; do not assume a newer model shares the old vocabulary.
  • Account for multimodal inputs—images and audio can consume a large token or patch budget.
  • Monitor for silent truncation when chunking or prompt assembly is measured in characters.
  • Test tokenization on real domain vocabulary, not only generic example sentences.
19
RECALL

Knowledge check

Why might “Oracle23ai” become three tokens instead of one?
It is rare in general training data, so a subword tokenizer represents it by combining smaller, more frequent pieces from its vocabulary.
What does a token ID actually index into?
The fixed vocabulary of the specific tokenizer that produced it—not a universal table shared across models.
How do vision transformers get token-like input from an image?
The image is split into fixed-size patches, each of which is embedded and processed similarly to a text token.
Why is chunk size measured in tokens rather than characters?
Both the embedding model and the LLM enforce limits on sequence length in tokens, and the token-to-character ratio is not constant.

CAREER PRACTICE

Interview questions

Why do subword tokenizers exist instead of word-level or character-level ones?
They balance vocabulary size against sequence length while still representing unseen words by combining known pieces, which neither pure word-level nor pure character-level tokenizers do well.
How would you estimate token cost for a RAG pipeline before deployment?
Run representative documents and queries through the target tokenizer, measure tokens per chunk and per query, and multiply by expected request volume and retrieved-chunk count.
What breaks if you swap an embedding model without checking its tokenizer?
Token IDs and resulting embeddings become inconsistent with the rest of the index, silently degrading retrieval quality.
How do multimodal models extend the token idea?
They convert images or audio into patches or frames that are embedded and sequenced alongside or instead of text tokens, using the same transformer machinery.
