01 · CONCEPT FIRST

The output head: one last projection, over the whole vocabulary

After the last transformer block finishes, each position holds one final hidden vector — a few thousand numbers summarizing everything attention and the feed-forward layers decided mattered for predicting what comes next. The output head (also called the unembedding or language-modeling head) is one learned matrix that projects that single vector into exactly one raw score per token in the vocabulary — its logits. Softmax then turns those logits into a probability distribution that sums to one.

Concept 01 already counted this matrix's parameters in passing, as one line in a parameter budget. This concept opens what that line actually does: turn geometry into a probability over a fixed, discrete set of tokens.

First memory: one hidden vector in, one logit out per vocabulary token, then softmax.
02 · WHY IT EXISTS

A model thinks in vectors; a vocabulary is a fixed, discrete list

Everything inside the block stack — embeddings, attention outputs, feed-forward outputs — is a vector in some continuous space. But the model must commit to one discrete choice from a fixed vocabulary of tens of thousands of tokens. Something has to bridge "a point in a few-thousand-dimensional space" to "a score for each of those specific tokens." That bridge is the output head.

WHAT THE BLOCK STACK PRODUCES

One continuous vector, the same size for every input position.

WHAT THE OUTPUT HEAD PRODUCES

One score for every token the vocabulary contains, however large it is.

04 · TECHNICAL MECHANISM

The six moving pieces

FINAL HIDDEN STATE

One vector per position

The block stack's last output — everything attention and feed-forward layers decided mattered.

OUTPUT HEAD MATRIX

One row per vocabulary token

A learned linear projection from hidden-vector size to vocabulary size.

LOGIT

One raw score per token

The dot product of the hidden vector with one row of the output head.

WEIGHT TYING

Optional shared matrix

Reusing the input embedding table, transposed, instead of learning a second matrix.

SOFTMAX

Logits to probabilities

Normalizes every logit into a positive weight that sums to one across the whole vocabulary.

PROBABILITY DISTRIBUTION

Handed to decoding

Exactly what Concept 07's greedy, temperature, top-k, and top-p rules already consume.

06 · IMPORTANT DISTINCTIONS

Terms that collapse into "the model's output"

TermWhat it actually isCommon confusion
LogitA raw, unnormalized score for one tokenConfused with a probability
Output headA learned matrix, one row per vocabulary tokenConfused with the embedding table when they are not tied
Weight tyingReusing the embedding matrix as the output head, transposedAssumed to be required, or assumed to change the mechanism's shape
This softmaxA single, final normalization over the entire vocabularyConfused with attention's per-position softmax over keys (Concept 04)

That last row matters: Concept 04's softmax normalizes attention weights over a handful of positions; this softmax normalizes logits over the entire vocabulary, once per generated token — same function, completely different inputs and purpose.

07 · COMMON MISTAKES

What beginners often misunderstand

"Logits are already probabilities."

They are raw scores; only softmax turns them into a distribution that sums to one.

"The output head only scores plausible tokens."

It computes one logit for every token in the vocabulary, every single step, regardless of how implausible most turn out to be.

"The output head is unrelated to the embedding table."

It can be tied to it directly — the same matrix, transposed — or learned separately; both are common.

"A bigger vocabulary means a bigger hidden state."

Vocabulary size changes the output head and embedding table's size, not the hidden dimension moving through the blocks.

"Decoding decides how many logits get computed."

All |vocabulary| logits already exist before any decoding rule — greedy, temperature, top-k, or top-p — even looks at them.

"Softmax only happens inside attention."

Attention's softmax and this final vocabulary-wide softmax are separate uses of the same function.

04
INTUITION

A giant scorecard, filled out all at once

Picture the final hidden vector as a fully filled-out request form. The output head is a scorecard with one line for every word in the vocabulary — tens of thousands of lines — and it scores how well the form matches every single line, simultaneously, in one matrix multiplication.

Analogy boundaryThis is a real matrix multiplication over every vocabulary row, not a search or a lookup. Nothing here narrows the candidate set the way a retrieval query would — every line gets scored, every single time, whether or not it ends up mattering.

06
MECHANISM

Two paths to the same shape: tied and untied

TIED OUTPUT HEAD
Take the input embedding matrix, already trained
Use its transpose directly as the output head
Multiply the final hidden vector by that transpose
Get one logit per vocabulary token — no second matrix learned
UNTIED OUTPUT HEAD
Initialize a second matrix, separate from the embedding table
Train it independently during pretraining
Multiply the final hidden vector by that separate matrix
Get one logit per vocabulary token — using different learned numbers

Both paths produce a vector of exactly |V| logits. Tying only decides which numbers fill the matrix that produces them, not how many numbers come out or what happens to them next.

08
ARCHITECTURE

One projection, sitting right before decoding

Prompt tokens↓ Embedding lookup↓ + positional encoding↓ Transformer blocks↓ Final hidden state↓ Output head↓ Logits → softmax↓ Decoding (built)

Whether the tokens came from a system instruction, retrieved evidence, or the user's question, they all pass through this identical output-head-then-softmax step at every generation step — retrieval and context construction only change what enters the block stack, never how the output head sizes or runs.

09
MATHEMATICS

The projection, softmax, and what tying saves

z = h · W_outᵗ + b

h is the final hidden vector (length d_model), W_out has shape |V| × d_model so each row produces one logit, and b is an optional per-token bias of length |V|.

softmax(z)_i = exp(z_i) / Σ_j exp(z_j)

This is the same softmax function Module 01 Concept 07 already derived with a temperature term for decoding; here it runs once, plain, to turn logits into the distribution decoding then samples from.

Weight tying: W_out = W_embᵗ → saves |V| · d_model parameters

Concept 01's toy parameter count used V=1000, d=64 and treated the output head as untied, adding 64,000 parameters on top of the embedding table's own 64,000. Tying the two matrices would remove that second 64,000 entirely, at the cost of forcing the output head to use exactly the embedding table's geometry.

WORKED EXAMPLE

Reproducing Concept 07's exact distribution by hand

Toy 2-dimensional final hidden vector after "…allows": h = [1, 1]. Toy output-head rows for the five candidate tokens Concept 07 already used: row(12)=[0.95,0.95], row(10)=[0.75,0.75], row(unlimited)=[0.70,0.70], row(several)=[0.55,0.55], row(many)=[0.30,0.30].

logits: h·row = [1.90, 1.50, 1.40, 1.10, 0.60] (sum of each row's two entries, since h=[1,1])
softmax: e^1.90≈6.69, e^1.50≈4.48, e^1.40≈4.06, e^1.10≈3.00, e^0.60≈1.82; sum≈20.05
distribution ≈ [33.3%, 22.4%, 20.2%, 15.0%, 9.1%]

Within rounding, that is the exact 34/22/20/15/9% distribution Concept 07 used when it first showed you this scenario's decoding step. Concept 07 started from the distribution; this concept just showed the matrix multiplication and softmax that actually produce it.

12
CODE

The output head, from scratch

PYTHON · NUMPY-STYLE PSEUDOCODE 
import numpy as np

def softmax(x, axis=-1):
    x = x - np.max(x, axis=axis, keepdims=True)
    exp = np.exp(x)
    return exp / np.sum(exp, axis=axis, keepdims=True)

def output_head(hidden, W_out, bias=None):
    # hidden: (d_model,)   W_out: (vocab_size, d_model)
    logits = W_out @ hidden
    if bias is not None:
        logits = logits + bias
    return logits                        # (vocab_size,)

def next_token_distribution(hidden, W_out, bias=None):
    logits = output_head(hidden, W_out, bias)
    return softmax(logits)               # sums to 1 over the vocabulary

# weight tying: reuse the embedding table as the output head
def tie_weights(embedding_table):
    return embedding_table                # same matrix, used as W_out
13
ECOSYSTEM

What production libraries actually call this

In Hugging Face transformers, this projection is typically a module named lm_head — an nn.Linear layer from the hidden size to the vocabulary size — with a config flag such as tie_word_embeddings deciding whether it shares parameters with the input embedding layer. Inference engines built for throughput, such as vLLM or TensorRT-LLM, fuse this final matrix multiply, the softmax, and the first decoding step into optimized kernels rather than running them as separate operations — the mathematics stays identical to the from-scratch version above, only the execution is different.

16
DIAGNOSIS

Failure modes

SKIPPED SOFTMAX

Comparing raw logits

Treating logits as probabilities skips the normalization step entirely.

SHAPE MISMATCH

Tying gone wrong

Tying weights when the embedding and hidden dimensions differ requires an adapter, or it silently breaks.

VOCAB DRIFT

Resized tokenizer, stale head

Adding special tokens without resizing the output head leaves new tokens with no learned row.

NUMERIC OVERFLOW

Naive exponentiation

Computing softmax without subtracting the maximum logit first can overflow for large logit values.

TOP-K CONFUSION

Mixing up two stages

Top-k truncation runs after all |V| logits exist — it never shrinks the output head itself.

BIAS OMITTED SILENTLY

Config mismatch

Expecting a per-token bias term that a specific checkpoint's output head does not actually include.

18
REALITY

Production implications

  • Large vocabularies (100k+ tokens) make the final projection and softmax a real share of per-token compute, distinct from attention cost.
  • Untied output heads add real memory: |V|·d_model extra parameters that a tied model does not carry.
  • Adding special or domain tokens requires resizing the embedding table and the output head together, or generation for those tokens breaks silently.
  • Numerically stable softmax implementations subtract the maximum logit before exponentiating, to avoid overflow at realistic logit magnitudes.
  • Logit-level interventions — temperature, penalties, logit bias, structured-output constraints — all modify this vector before Concept 07's decoding rules ever run.
  • Verify a checkpoint's actual tying configuration rather than assuming it from the model family name alone.
19
RECALL

Knowledge check

What two inputs does the output head projection combine to produce a logit?
The final hidden vector for one position, and one row of the output head's weight matrix — their dot product, plus an optional bias, is the logit.
Why must the output head have exactly |vocabulary| rows?
Because softmax needs exactly one logit per possible next token to produce a distribution over the whole vocabulary; any fewer rows and some tokens could never be predicted.
What does weight tying change, and what does it leave the same?
It changes which numbers fill the output head's matrix, reusing the embedding table's numbers instead of learning new ones; it leaves the output shape — one logit per token — completely unchanged.
Why is this concept's softmax a different use of the same function as Concept 04's attention softmax?
Concept 04's softmax normalizes attention scores over a handful of positions inside every block; this concept's softmax normalizes logits over the entire vocabulary, once, at the very end of the forward pass.

21
FEEDBACK

Solution and teach-back

Open one worked reasoning pattern
Swapping in a tied output head only changes which numbers occupy each row — the rows now equal the embedding table's rows, transposed into the projection — so the logits you compute will generally come out different from an independently-learned untied matrix. What stays identical is the shape of the computation: one dot product per candidate token, still producing exactly one logit per token, still normalized by the same softmax afterward. Tying is a decision about where the numbers come from, not about what the mechanism computes or how many outputs it produces.

23
CAREER PRACTICE

Interview questions

Explain what the output head is and how it relates to the input embedding table.
It is a learned matrix that projects the final hidden vector into one logit per vocabulary token; it can be tied to the input embedding table (used transposed, with no extra parameters) or learned as a separate, untied matrix.
Why does weight tying reduce parameter count, and by how much?
It reuses the embedding table instead of learning a second matrix of the same shape, saving |V|·d_model parameters — the exact quantity Concept 01's toy parameter count added on top of the embedding table when it assumed an untied head.
Where does a logit-bias or structured-output constraint get applied, mechanically?
Directly to the logit vector produced by the output head, before softmax runs — it reshapes the distribution decoding will later sample from, without changing the projection mechanism itself.
A colleague says a larger context window makes the output head bigger. How do you respond?
The output head's size depends only on vocabulary size and hidden dimension; a longer context changes how much the block stack processes upstream, not the shape of this final projection.
