01 · CONCEPT FIRST

Training versus inference

Training uses data and an objective to update learnable parameters. Pretraining is the broad initial training that creates a reusable base model. Fine-tuning starts from pretrained parameters and updates all or some trainable parameters for a narrower behavior, domain, or task.

Inference uses fixed trained parameters to process a new input and produce an output. Prompting, retrieving documents, querying Oracle, and adding context can change the input and output while leaving the model’s weights unchanged.

First memory: training learns or changes parameters; inference uses current parameters.
02 · WHY IT EXISTS

Why not use one stage for everything?

Broad pretraining learns reusable patterns from enormous datasets. Fine-tuning can specialize behavior more persistently. Inference must answer individual requests quickly without retraining the model each time. RAG and tools inject current or private information at inference because repeatedly retraining for every document update would be slow, costly, and difficult to govern.

CHANGE BEHAVIOR OR CAPABILITY

Consider supervised tuning, preference optimization, continued pretraining, or adapters—with evaluation and versioning.

SUPPLY CURRENT FACTS

Prefer retrieval, databases, APIs, or other tools at inference time.

03 · CONCRETE EXAMPLE

The leave policy changes on Monday

If the carry-forward policy changes, ordinary RAG re-indexes the approved document. The next query retrieves the new passage and gives it to the same model. No LLM weight update is required.

If the assistant consistently ignores a required output schema, you might improve the prompt, constrain decoding, or fine-tune on high-quality schema examples. If the model lacks the organization’s terminology across many tasks, carefully evaluated domain-adaptive continued pretraining might be considered.

POLICY UPDATE

Update document and index. Model weights stay fixed.

EXACT BALANCE

Query Oracle during inference. Model weights stay fixed.

PERSISTENT RESPONSE STYLE

Prompt first; fine-tune only when justified. Weights may change.

04 · TECHNICAL MECHANISM

The lifecycle stages

PRETRAINING

Create the base

Update many parameters on broad data using a self-supervised objective.

CONTINUED PRETRAINING

Shift domain exposure

Resume the pretraining objective on additional domain or language data.

SUPERVISED FINE-TUNING

Teach input-output behavior

Update parameters from curated instruction-response or labelled examples.

PREFERENCE / ALIGNMENT

Prefer desired outputs

Use comparisons, rewards, or preference objectives to shape behavior.

PEFT · LoRA

Train small additions

Freeze base weights and learn small adapter parameters.

INFERENCE

Use the artifact

Keep parameters fixed while processing prompts, context, and tool results.

06 · IMPORTANT DISTINCTIONS

Methods that are often confused

Method Weights? Primary purpose
Pretraining Many updated Learn broad reusable representations/capabilities
Full fine-tuning Most/all updated Specialize model behavior
LoRA / adapters Base frozen; small parameters trained Efficient specialization
Prompting Unchanged Condition one inference request
RAG Unchanged in ordinary RAG Supply external evidence
In-context learning Unchanged Demonstrate a task inside the context

Quantization changes numerical representation for efficiency; it is not automatically fine-tuning. QLoRA combines a frozen quantized base with trainable low-rank adapters.

07 · COMMON MISTAKES

What beginners often misunderstand

“Every prompt trains the model.”

No. Standard inference does not update model parameters.

“RAG fine-tunes on retrieved documents.”

Ordinary RAG places retrieved content in runtime context.

“Fine-tuning is the best way to add changing facts.”

Frequently changing authoritative knowledge generally belongs in retrieval or tools.

“LoRA changes nothing in the model.”

It trains additional low-rank parameters while freezing the base weights.

“Inference means deterministic output.”

Inference can include stochastic sampling; token sampling belongs to Concept 7.

“Training loss proves production quality.”

Held-out evaluation and system-level testing are still required.

08 · YOUR PROJECT MAPPING

Choose the right lever for Oracle RAG

NEW POLICY VERSION Re-index retrieval

Do not tune the model merely to memorize the new text.

EMPLOYEE BALANCE Oracle inference-time lookup

Current personal data remains in the governed database.

COMPANY TERMINOLOGY Prompt, glossary retrieval, then evaluate tuning

Start with the least invasive reliable method.

STRICT ROUTING FORMAT Schema, validation, classifier, or tuning

Choose using measured failure rates and risk.

LangChain or LangGraph can orchestrate both fixed-model inference and calls to separately trained adapters. They do not decide whether tuning is necessary.

DEPENDENCIES

Prerequisite check

  • Parameter: a learned numerical value.
  • Loss: scalar training objective to minimize.
  • Gradient: local sensitivity of loss to a parameter.
  • Checkpoint: saved parameter and training state.
  • Inference context: runtime inputs that do not become persistent parameter updates.
04
INTUITION

Study, coaching, and an open-book exam

Pretraining resembles broad study; fine-tuning resembles focused coaching; inference resembles taking a new exam using the learned state. RAG is an open-book mechanism that supplies selected references during the exam.

Analogy boundaryNeural parameters are not human memories, and in-context examples can alter runtime behavior without durable learning.

MECHANISM

One optimization step

Batch examples
Forward pass produces predictions
Loss compares predictions with objective
Backpropagation computes gradients
Optimizer updates trainable parameters
Evaluation decides whether to save checkpoint

Inference usually stops after the forward pass and decoding/tool workflow. It does not run backpropagation or an optimizer update.

09
MATHEMATICS

Gradient descent and low-rank adaptation

Full update: θt+1 = θt − η ∇θL(θt; B)

η is the learning rate, B is a batch, and the gradient points toward locally increasing loss, so subtraction aims to reduce it.

LoRA: W′ = W₀ + ΔW, where ΔW = BA and rank(BA) ≤ r

The base matrix W₀ stays frozen while smaller matrices A and B are trained. Inference uses the base plus learned update.

10
WORKED EXAMPLE

A one-parameter training step

For prediction ŷ = wx, let x=2, target y=10, initial w=3, and loss L=(ŷ−y)².

ŷ=6; L=(6−10)²=16; dL/dw=2(wx−y)x=2(6−10)2=−16
With η=0.1: w′=3−0.1(−16)=4.6

The weight changed because training applied a gradient update. During inference with w=4.6, computing ŷ alone does not alter w.

    optimizer.zero_grad()

    loss.backward()

# Inference: parameters stay fixed

    output = model(runtime_input)
13
ECOSYSTEM

Full tuning, LoRA, and QLoRA

Full tuning stores and optimizes a large trainable state. LoRA freezes pretrained weights and trains low-rank matrices. QLoRA keeps a quantized frozen base while backpropagating into LoRA adapters, reducing memory use. These efficiency methods do not remove the need for high-quality data and evaluation.

CORRECTION

Misconceptions

Incorrect belief Correction
Prompt history updates weights It changes context, unless a separate training pipeline later uses the data.
Fine-tuning guarantees factual accuracy It can alter behavior but does not guarantee current evidence or provenance.
LoRA is inference-only Adapter parameters are trained and persist.
Evaluation loss equals user value Production tasks require multiple behavioral and operational metrics.
18
REALITY

Production implications

  • Version datasets, code, objectives, seeds, base checkpoints, adapters, and evaluation suites.
  • Separate training compute/security environments from serving.
  • Record lineage from base model to deployed artifact.
  • Run capability, safety, privacy, bias, and regression evaluations after every update.
  • Monitor cost and latency separately for training and inference.
  • Preserve rollback paths for checkpoints and adapters.
19
RECALL

Knowledge check

Does RAG update model weights?
Ordinary RAG does not. It changes inference context using retrieved evidence.
What does LoRA train?
Small low-rank parameter matrices while the pretrained base weights remain frozen.
Continued pretraining versus SFT?
Continued pretraining generally reuses a self-supervised objective on domain data; SFT learns from labelled or instruction-response examples.
What distinguishes inference?
The deployed parameters are treated as fixed; the system computes outputs without optimizer updates.

23
CAREER PRACTICE

Interview questions

When would you choose RAG over fine-tuning?
For current, private, attributable, frequently changing knowledge that should remain externally governed.
Full fine-tuning versus LoRA?
Full tuning updates broad model state and costs more; LoRA freezes the base and trains low-rank updates, improving storage and training efficiency with different capacity trade-offs.
What is train-serving skew?
Training/evaluation inputs or processing differ from production, producing unexpected behavior.
How would you prove tuning helped?
Use held-out task and safety suites, compare against prompt/RAG baselines, measure regressions and operations, and keep a rollback candidate.
