01 · CONCEPT FIRST

What does Generative AI mean?

Generative AI is a class of AI systems that produces content from an input or instruction. The output may be text, code, an image, audio, video, or another form of data.

The word generative describes the system’s job: it constructs an output for the current request. A text model creates a sequence of words or tokens; an image model creates pixel patterns; an audio model creates a waveform. The output type changes, but the central idea stays the same.

Input does not mean only a short prompt

The model may receive an instruction, earlier conversation, an image, retrieved passages, database results, tool outputs, or a combination of them. Everything supplied for the current request helps condition what it generates.

INPUT

“Explain how diabetes affects the human body in language a teenager can understand.”

OUTPUT

A newly produced explanation whose topic, tone, and level follow the instruction and the patterns learned during training.

User → Prompt and context → Generative model → Generated response

What does “new content” mean?

It means the system produced this output for this request instead of selecting one fixed answer from a normal lookup table. It does not guarantee that every idea is original, that every claim is factual, or that the output is safe to use.

Core idea: learn patterns → receive an input and context → generate content. Generation describes how the output is produced, not whether the output is true.
02 · WHY IT EXISTS

What problem does it solve?

Many software problems have one exact result. A calculator should return the same sum each time, and a database lookup should return the stored row. But language and creative tasks often have many acceptable outputs. There is no single fixed sentence that explains every policy to every employee.

Generative AI is useful when software must create an output that fits a request: drafting an email, rewriting technical material for a beginner, summarizing several passages, answering a question conversationally, producing code, or creating an image.

DETERMINISTIC SOFTWARE

Explicit rules + exact data → expected result

GENERATIVE AI

Instruction + context + learned patterns → one suitable response

Why is an LLM alone not enough for company questions?

Its learned parameters are not a live connection to your company. The model does not automatically know private documents, the latest Oracle records, a policy changed this morning, or which employee is allowed to see which data.

Worse, the model’s job is to continue text plausibly. When evidence is missing, it may still produce confident-looking language. This creates the central RAG problem: how do we give a language generator the right external evidence at answer time?

Why RAG exists: the LLM is useful for language, but external systems must supply current, private, authoritative, and access-controlled knowledge.
03 · CONCRETE EXAMPLE

A company-policy assistant

Imagine that your company stores one thousand HR documents. One current, authorized passage says:

Employees can work remotely up to three days per week.

An employee asks, “How many days can I work remotely?” An ordinary public LLM cannot be expected to know this private rule. Even if it guesses “three,” a guess is not acceptable evidence.

What the RAG system does

  1. Receives the employee’s question.
  2. Searches the authorized company knowledge base.
  3. Finds the passage that directly answers the question.
  4. Adds the question and passage to the LLM’s input.
  5. Asks the LLM to answer using that passage.
QUESTION

How many days can I work remotely?

RETRIEVED CONTEXT

Employees can work remotely up to three days per week.

GENERATED ANSWER

You can work remotely up to three days per week.

Who contributed what?

The retriever did not write the final sentence; it found evidence. The LLM did not discover the company policy from its parameters; it expressed the supplied evidence in natural language.

Evidence path: company document → retrieved passage → LLM input → answer. If the passage cannot be found or the employee cannot access it, the system should not invent the policy.
04 · TECHNICAL MECHANISM

What happens internally?

There are two different moments to understand: training, when the model learns patterns, and inference, when the trained model generates an answer for a user.

During training

The model processes many examples. When its prediction differs from the training example, a learning algorithm adjusts millions or billions of internal numerical values called parameters. Repeating this process teaches the model statistical relationships between words, ideas, structures, and styles.

The model does not normally preserve the training material as a neat library of questions and answers. What it carries forward is a distributed set of learned parameters.

During inference

  1. Tokenize: convert the prompt into smaller units called tokens.
  2. Process context: use the prompt, conversation, and any supplied evidence to form the current context.
  3. Predict: assign probabilities to possible next tokens.
  4. Select: choose one token according to the decoding settings.
  5. Repeat: append that token and predict again until a stopping condition is reached.
Prompt → Tokens → Next-token probabilities → Selected token → Repeat

A response therefore emerges token by token. This explains two important properties: the wording can vary between runs, and plausible wording can be generated without a factual source.

CONCEPTUAL PSEUDOCODE 
response = ""
while not finished:
    probabilities = model.predict_next(prompt + response)
    next_token = choose(probabilities)
    response = response + next_token
For now: understand training versus inference and the token-by-token loop. Tokens, probability, transformers, attention, and decoding each receive their own later lesson.
05 · ARCHITECTURE / FLOW

Where does generation sit in RAG?

RAG means Retrieval-Augmented Generation. The name describes the online answering sequence: retrieve evidence, augment the model’s input with that evidence, and generate an answer.

Retrieval Find information relevant to the question.
Augmented Place the selected information inside the model’s context.
Generation Produce an answer that uses the supplied context.

The system actually has two lifecycles

OFFLINE · PREPARE KNOWLEDGE

Documents → parse → chunk → embed → index

ONLINE · ANSWER A QUESTION

Question → retrieve → construct context → generate → verify

The offline lifecycle makes knowledge searchable before a user asks anything. The online lifecycle uses that prepared index to answer a particular question. Document updates may cause part of the offline lifecycle to run again.

06 · IMPORTANT DISTINCTIONS

Similar words, different engineering jobs

A reliable RAG system depends on assigning each job to the correct component. If we ask an LLM to perform an exact lookup, or mistake a vector database for an embedding model, the architecture becomes unreliable.

GENERATE Explain a policy

Produces new wording from supplied facts.

RETRIEVE Find the policy

Searches existing documents for evidence.

LOOK UP Get leave balance

Reads an exact Oracle row or API value.

CALCULATE Compute remaining days

Applies deterministic rules or arithmetic.

Parsing versus extraction

Parsing turns a file’s structure into usable content: pages, paragraphs, tables, headings, and metadata. Extraction selects particular facts from that content, such as a policy effective date or employee category. Parsing gives the system readable material; extraction identifies specific fields.

Embedding model versus vector database

An embedding model converts text into numerical vectors that represent useful semantic patterns. A vector database or vector index stores those vectors and searches them efficiently. The model creates the representation; the database stores and searches it.

Component Question it answers Example output
Parser What content and structure are in this file? Heading + paragraph + table
Embedding model How can this text be represented numerically? A vector
Vector index Which stored vectors are nearest to this query? Candidate chunk IDs
Oracle / SQL What exact structured record matches? Leave balance = 12
LLM How should supplied evidence be explained? Readable answer
Design rule: parse files, embed meaning, search an index, retrieve documents, look up records, calculate exact results, and use generation to explain verified information.
07 · COMMON MISTAKES

What beginners often misunderstand

These mistakes are dangerous because the resulting system can still look impressive during a short demonstration. A fluent interface can hide an incorrect architecture.

“The LLM is a database.”

It generates from learned parameters. It does not reliably return an exact stored company record. Use the authoritative database or API.

“Fluent means factual.”

Smooth grammar is evidence of language ability, not proof that a claim is supported. Require retrieved evidence, validation, and citations.

“RAG means PDF → LLM.”

A real pipeline includes parsing, cleaning, chunking, embedding, indexing, retrieval, filtering, authorization, context construction, and evaluation.

“RAG fixes every hallucination.”

Retrieval can return irrelevant or outdated passages, and the model can ignore good evidence. Retrieval and generation must both be evaluated.

“More context is always better.”

Extra passages can distract the model, increase cost, and bury the useful evidence. Context should be selected deliberately.

“The LLM should calculate exact values.”

Use SQL, APIs, rules, or calculators for deterministic work. Let the LLM explain their verified results.

How can an answer be fluent but unsafe?

Suppose the assistant correctly retrieves a general carry-forward policy but accidentally exposes another employee’s leave balance because access control was applied after retrieval. The sentence may be clear and factually correct, yet the answer is unsafe because confidential data reached the wrong user.

Quality has several dimensions: readable language, correct evidence, current data, correct authorization, and appropriate uncertainty. Fluency covers only the first.
08 · YOUR PROJECT MAPPING

How this maps to Oracle, metadata, and Text-to-SQL

Now apply the concept to the project question: “What is my remaining leave balance, and summarize the relevant carry-forward policy?” This is not one AI task. It is a coordinated workflow containing identity, structured lookup, document retrieval, generation, and verification.

IDENTITY + ACCESS Who is asking?

Authenticate the user, resolve the employee ID, and determine which records and policies the user may access.

ORACLE / TEXT-TO-SQL What is the exact balance?

Translate the balance request into constrained SQL or select a prepared query, validate it, and query the authoritative structured record.

METADATA + RETRIEVAL Which policy applies?

Filter policy content by region, employment type, leave type, effective date, version, and permission before semantic retrieval.

LLM GENERATION How should it be explained?

Combine only the verified balance and retrieved policy passage into a clear answer that cites its source.

The seven-node answer flow

User identity → Authorize scope → Oracle balance lookup → Metadata-filtered policy retrieval → Construct grounded prompt → LLM generation → Verify, cite, answer

What must the generator never invent?

  • The employee’s leave balance, used days, entitlement, or any other exact database value.
  • The policy’s carry-forward limit, expiry date, eligibility rule, exception, or effective version.

When should the system abstain?

It should not give a definite answer when identity or authorization fails, the Oracle lookup fails, no applicable current policy is retrieved, sources conflict, or the retrieved evidence does not support the requested claim. A useful abstention names the missing requirement instead of merely saying “I don’t know.”

FUTURE IMPLEMENTATION SHAPE 
user = authenticate(request)
scope = authorize(user)
balance = oracle.query(validated_sql, employee_id=user.id)
policy = retriever.search(question, metadata=scope)

if balance is missing or policy is unsupported:
    return abstain_with_reason()

answer = llm.generate(question, balance, policy)
return verify_and_cite(answer)

03
DEPENDENCIES

Prerequisite check

This first concept has no course prerequisite. Three small ideas are enough:

  • Data: recorded examples such as text, images, audio, tables, or code.
  • Model: a parameterized computational function whose behavior can be fitted from data.
  • Probability: a number between 0 and 1 representing uncertainty, with mutually exclusive outcomes summing to 1.
Thirty-second probability refresher
If a generator assigns probabilities 0.5, 0.3, and 0.2 to three possible next tokens, their sum is 1. Sampling does not always select 0.5; it selects outcomes with those long-run frequencies. The most probable outcome is not the only possible one.
04
INTUITION

A map of plausible artifacts

Imagine studying thousands of building plans. A discriminative system might learn to label each plan “residential” or “commercial.” A generative system learns enough structure to propose another plan that resembles the collection—rooms connect, walls align, and dimensions look plausible.

The generator is not a filing cabinet that finds a plan. It has learned a landscape of possibilities. A prompt or other condition points toward one region; sampling chooses a path through it. More capable models learn richer structure, but the central idea remains: learn patterns, then produce a candidate consistent with them.

Where the analogy breaksA learned model does not necessarily understand buildings, physical laws, or safety codes. It may reproduce correlations without possessing the external knowledge needed to validate the result.
05
PRECISION

Formal definition and boundaries

Generative AI is the class of AI models and systems that learn structural and statistical characteristics of data and use the learned mechanism to produce derived synthetic content. The content can be text, images, audio, video, code, molecules, 3D structures, or combinations of modalities.

Unpacking the definition

  • Model: parameters θ encode behavior learned during training.
  • Distribution: the model assigns probability or density to possible outputs, explicitly or through a generative process.
  • Condition: generation may depend on a prompt, image, class label, retrieved passages, or other context c.
  • Sample: inference produces one candidate from many possible candidates.
  • Synthetic: the output is machine-produced. It may be useful and original, derivative, memorized, or erroneous.

Classical generative learning versus modern “GenAI”

In classical supervised learning, “generative” can mean modelling p(x|y) and p(y) so Bayes’ rule can classify. Modern usage usually emphasizes models that synthesize rich content. They share the idea of modelling how data could be generated, but the scopes are not identical.

06
MECHANISM PREVIEW

Training and generation are different operations

OFFLINE · TRAINING
Collect and prepare examples
Represent them numerically
Predict / reconstruct / denoise
Measure error or objective
Update parameters θ repeatedly
Save a trained model
ONLINE · INFERENCE
Receive condition c
Compute output probabilities
Select or sample an outcome
Feed state into next step
Stop at a rule or limit
Return and validate artifact

Training changes the model’s parameters. Ordinary inference usually does not. Supplying a prompt gives temporary context; it does not normally retrain the model.

Prompt / condition c
Model parameters θ
Probability distribution

09
MATHEMATICS

Learn a distribution, then sample

Let training examples be drawn from an unknown real-world data distribution p_data(x). We choose a model family p_θ(x|c), where θ are learned parameters and c is an optional condition.

Training goal (maximum likelihood):
θ* = arg maxθ Σi=1..N log pθ(xi | ci)

Maximizing log-likelihood rewards parameters that assign high probability to observed training examples. Equivalently, minimizing negative log-likelihood penalizes surprising observed data.

Autoregressive text factorization:
pθ(x1:T | c) = ∏t=1..T pθ(xt | x<t, c)

A sequence probability becomes a product of next-token probabilities. At each step, the model conditions on the preceding tokens and context. This equation describes probability, not factual verification.

Temperature-adjusted sampling:
q(xt=j) = exp(zj/τ) / Σk exp(zk/τ)
Symbol Meaning
x A data item or generated sequence
c Condition: prompt, label, image, or retrieved evidence
θ Learned model parameters
z_j Raw score (logit) for candidate j
τ Temperature; lower sharpens, higher flattens
Do not over-interpret likelihoodA high-probability continuation is one the model considers plausible under its learned patterns. Plausibility, truth, usefulness, fairness, safety, and originality are different properties.

WORKED EXAMPLE · TOY ONLY

A tiny next-word generator by hand

Suppose a toy corpus contains ten sentences beginning “RAG is …”:

Next word Count Maximum-likelihood probability Cumulative interval
useful 5 5/10 = 0.50 [0.00, 0.50)
reliable 3 3/10 = 0.30 [0.50, 0.80)
risky 2 2/10 = 0.20 [0.80, 1.00)
  1. Estimate each probability from relative frequency.
  2. Draw a uniform random number u between 0 and 1.
  3. If u = 0.72, it lies in [0.50, 0.80), so the sample is reliable.
  4. A greedy decoder would always choose useful; sampling preserves diversity.

This intentionally tiny example proves only that generation can sample from a learned distribution. It is not the LLM lesson: contextual token probabilities, transformers, and decoding receive their own later treatment.

  const scaled = Object.entries(scores)
    .map(([token, score]) => [token, Math.exp(score / temperature)]);
  const total = scaled.reduce((sum, [, value]) => sum + value, 0);
  return scaled.map(([token, value]) => [token, value / total]);
}

function sample(distribution, random = Math.random()) {
  let cumulative = 0;
  for (const [token, probability] of distribution) {
    cumulative += probability;
    if (random < cumulative) return token;
  }
  return distribution.at(-1)[0]; // floating-point fallback
}

const distribution = softmax(logits, 1.0);
console.log(distribution);
console.log("RAG is", sample(distribution, 0.72));

Inspection questions: What changes if temperature approaches zero? Why is the random number injectable? Why is a floating-point fallback included? The interactive lab uses this same mechanism with a seeded random-number generator.

AUTOREGRESSIVE

Predict the next element

Encode and decode latents

GAN

Provides tractable likelihood in suitable architectures with constraints on transformations.

DIAGNOSIS

Failure modes and evidence

FABRICATION

Plausible but unsupported

Symptom: fluent false claim. Evidence: no supporting source or contradiction. Remedy: retrieve, cite, validate, abstain.

MEMORIZATION

Training data leakage

Symptom: near-verbatim sensitive or copyrighted material. Evidence: matching analysis. Remedy: data governance, privacy testing, filters.

MODE COLLAPSE

Missing diversity

Symptom: narrow repeated outputs. Commonly discussed for GANs. Remedy depends on objective, data, and training method.

BIAS

Unequal or harmful patterns

Symptom: systematic performance or representation differences. Remedy: scoped evaluation and risk controls, not a generic safety prompt.

DRIFT

World changed after training

Symptom: stale policies, people, prices, or facts. Remedy: external current sources and freshness-aware retrieval.

PROMPT SENSITIVITY

Small wording, large change

Symptom: unstable answers. Remedy: controlled prompts, structured outputs, test suites, and uncertainty handling.

MISCONCEPTIONS

Tempting mental models to discard

Incorrect belief Correct model
“It searches its training data for an answer.” Inference computes outputs from learned parameters and current context; literal memorization can occur, but generation is not ordinary record retrieval.
“The most fluent answer is the most true.” Fluency measures learned linguistic regularity, not external verification.
“Random means arbitrary.” Sampling is random under a structured learned distribution; candidates are not equally likely.
“Generative AI always creates something original.” Outputs range from novel combinations to close reproduction. Novelty requires separate measurement.
“An LLM is the same as Generative AI.” LLMs are a major subset. Image, audio, molecule, and other generators may use different architectures.
“RAG retrains the model with documents.” Typical RAG retrieves evidence at inference time and conditions generation; it does not update model weights.

PRODUCTION

A generator is one component, not the product

  • Quality: define task-specific correctness, usefulness, faithfulness, safety, and citation metrics.
  • Latency: model size, number of generated tokens, decoding method, network calls, and validation stages matter.
  • Cost: training, inference, input/output tokens, GPUs, storage, retrieval, and evaluation all contribute.
  • Security: prompts and outputs can expose sensitive data; retrieved content can carry malicious instructions.
  • Governance: record model, prompt, data, index, policy, and evaluation versions.
  • Human control: high-impact use cases need review, escalation, and clear responsibility.
  • Provenance: synthetic output should not be mistaken for a source. Preserve links to evidence and content history.
Production design ruleUse a generator for synthesis and language transformation. Use databases, retrieval, calculators, business rules, tools, and human review for the kinds of authority they actually possess.

KNOWLEDGE CHECK

Test the mental model

1. Does generation require randomness?
No. Greedy or otherwise deterministic decoding can select the same output for the same state. The model is still generative because it defines or realizes a content-generating mechanism; sampling is one decoding choice.
2. Why can a high-probability sentence be false?
The probability reflects patterns under the learned model and context. The objective is not automatically a truth-verification objective, and the model may lack current or private evidence.
3. Is a calculator generative AI?
Ordinary deterministic arithmetic is computation, not learned generative modelling. A generative model can emit arithmetic text, but correctness should be delegated to a calculator when exactness matters.
4. What does RAG change?
It retrieves external evidence and adds it to the model’s inference-time context. It does not inherently retrain the model or guarantee faithful use of the evidence.
5. What is the distinction between p(x|y) and p(y|x)?
A classical generative classifier models how features x arise given class y (plus class priors); a discriminative classifier directly models the label given features. Modern content generation often models p(x) or p(x|c) for rich artifacts.

A learned probability-producing mechanism that generates derived synthetic content, optionally conditioned on context.

INTERVIEW PRACTICE

Questions you should be able to defend

Conceptual: What makes a model generative?
It models or realizes a process capable of producing samples consistent with learned data structure, often as pθ(x) or pθ(x|c), rather than only mapping inputs to fixed labels.
Mathematical: Why use log-likelihood?
It converts products of probabilities into sums, improves numerical handling, and yields an objective that rewards probability assigned to observed examples.
Debugging: Same prompt, inconsistent answers—why?
Sampling, temperature, provider/model versions, hidden context, nondeterministic kernels, or external-tool variability. Capture configuration and traces before diagnosing.
System design: Where should exact facts come from?
Authoritative databases, retrieval systems, calculators, or tools. The generator should synthesize those results under validation.
Risk: Why can RAG still hallucinate?
Retrieval may fail, context may be irrelevant, or the generator may distort/extend evidence. Each stage requires separate evaluation.
Trade-off: Greedy versus sampling?
Greedy decoding is predictable but can be repetitive or locally suboptimal. Sampling provides diversity but increases variability; use case and evaluation determine the policy.
